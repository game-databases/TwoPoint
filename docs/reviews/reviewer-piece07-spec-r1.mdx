## Findings

### F1 — CRITICAL — §5 transition paragraph sanctions silent destruction of the canonical file and contradicts its own invariants

Location: spec §5 "Transition safety" bullet; §1 ("the only cross-stage
change is the ownership amendment").

What's wrong. Three connected defects:

1. After stage 7 lands, the file holds 5,850 v2 rows. The bullet still
   says an isolated `--only emit-stub-datasets` run "may still emit its
   legacy 0-row v1 file — harmless" and that "consumers reading the v1
   schema mid-transition see 0 rows (**today's status quo**)". Post-
   landing that overwrite is NOT today's status quo — it destroys the
   §5.4 single source and silently reopens the exact G1 gap this piece
   exists to close, until someone remembers to rerun `--only
   locale-proof`. Patch-day stage-by-stage reruns make this a realistic
   sequence, not a hypothetical.
2. The same bullet asserts "no stage ever deletes or truncates a file it
   does not own" while stage 5, having lost ownership, still writes
   (truncates) the path. "The single-writer invariant survives: exactly
   ONE stage owns the path" is false under the paragraph's own text.
3. "Stage 5's emission clause is retired" is ambiguous between retiring
   a DOC clause and removing the CODE path. §5 routes three DOC deltas
   to documentator seats and is silent on (a) whether
   `tools/stage5_emit_stubs.py` stops writing the file, and (b) the fate
   of stage-5's availability tests (piece-01 §3 acceptance "is
   regenerated on every run…" + §8 stage-5 fixture bullets).

Fix. Pick one, explicitly, as part of THIS piece's contract:

- Preferred: retire the emission in CODE inside this piece (delete/guard
  the stage-5 write — a few lines — and delete or repoint its two
  availability assertions/tests), keeping single-writer literally true;
  or
- keep the interim dual-emission but make it loud: stage 5 must detect
  non-v1/non-empty content at the path and refuse (exit 1 naming the
  conflict) instead of clobbering; and pin that only full runs may heal
  the path.

### F2 — MAJOR — AC5/L1 identity tier: expected value 297 is reproducible only under an unstated predicate

Location: §L1 `identityToPivot` schema (`identicalButTranslatedElsewhere`);
AC5 ("297 translated-elsewhere"); F8's gloss "(= translated elsewhere)".

What's wrong. Measured this session: of the 301 `Items/*_Name` keys where
ru == en, **297 differ in de** but **301 differ in SOME other holding
locale** (the residual 4 — `Items/DLC_Ghost/Mausoleum_Name`,
`Items/DLC_Space/Planetarium_Name`, `Items/Ghost_DLC/Dolly_Name`,
`Items/Ghost_DLC/Theremin_Name` — are identical-to-en in de yet differ
elsewhere). The field NAME ("translated elsewhere") implements to 301;
the pinned expected value 297 exists only under "de differs"
(verifyA #7 said exactly this). An honest builder fails AC5 or fudges.

Fix. Pin the predicate verbatim in `metricRule`, e.g.
`identicalButTranslatedElsewhere := <locale>==en AND de != en` (the
informative tier — it isolates keys untranslated in BOTH ru and de), or
re-freeze the number under whichever predicate is chosen; state how the
tier evaluates for the other 12 locales the artifact recomputes.

### F3 — MAJOR — L6 dangling-miss shape contradicts the measured corpus

Location: §L6 `registry_completeness.json` sample (`dangling:
[{termId: …, dev: "WantsMessage", onIds: [both ids]}]`); AC8 "the two
dangling IDs exact".

What's wrong. Measured (`locale_join_report.json` unresolvedIds + the
two stub payloads): there are **TWO DISTINCT termIds** — `-1451566921`
on `Unused_PersonalGoal_Item_Gym_Vaulting_Horse` and `-1172386361` on
`Unused_PersonalGoal_Item_AnyExterior` — and the `_dev` string is
`"Wants a {ITEM}"` on both. `WantsMessage` is the FIELD PATH, not the
dev value. The pinned one-object shape implies a single shared termId
and mislabels dev; a builder following it must fabricate a grouping or
drop a termId, and no verifier can reconcile AC8 against the corpus
through it.

Fix. Pin one row per dangling termId:
`{termId: -1451566921, fieldPath: "WantsMessage", dev: "Wants a {ITEM}", srcKind: "item", onIds: ["Unused_PersonalGoal_Item_Gym_Vaulting_Horse"]}`
plus the `-1172386361` twin — sorted by termId.

### F4 — MAJOR — RELATIONS.md edit routed to a seat that cannot hold it

Location: §5 Routing bullet ("RELATIONS.md's R4 routing note gains one
sentence … owned by the piece-01/piece-02 documentator seats").

What's wrong. RELATIONS.md is a GENERATED artifact — piece-02 §R7 pins
it as regenerated mechanically by `stage6_relink.py` from matrix +
ledgers, byte-deterministic, reruns byte-identical. A hand-edited
sentence is silently reverted on the next relink run (patch day).

Fix. Route the sentence into the generator (stage-6 code/template input)
as a code delta owned alongside the piece-1 revision, or drop the
RELATIONS.md leg and record the pointer in piece-02 prose only — either
way, name the mechanism, not just the seat.

### F5 — MAJOR — Tripwire semantics undefined for exact-match-direction members

Location: §L6.3 comparison rules; §6 regressionVector directions.

What's wrong. Directions are pinned as higher-better / lower-better /
"structural counts exact-match", but the four comparison bullets only
define worse/equal/better for DIRECTIONAL members. A CHANGED
exact-match member at the same buildId (matrixKeyDiff 0→1, orphansB
0→2, chromeSurfaces 16→15) satisfies neither "any member WORSE by its
pinned direction" nor "strictly better/equal" — exit behavior is
implementer's choice. AC10 only exercises a coverage-count drop, so the
gap ships untested.

Fix. Add one rule — any CHANGE in an exact-match-direction member counts
as worse ⇒ `REGRESSION:` line + baseline untouched + exit 1 — and a
fixture leg that flips one structural member.

### F6 — MAJOR — Optional alias-input branch has no test leg

Location: §4 OPTIONAL input paragraph vs §10 (L2/L3/runner bullets).

What's wrong. The alias-present branch is first-class contract (course
name-columns computed THROUGH `course-name-aliases.jsonl`,
`inferred:true` + method carried per cell, method recorded in the
metricRule appendix, `course-name-join-open` suppressed) — and §10 never
exercises it. Dormant contracted code without a fixture violates this
pipeline's own precedent (untriggerable arms stay synthetically tested;
piece-1 Revision 5 kept the R8 arms tested precisely for this reason).
TestWriter building blind will ship the branch untested.

Fix. One fixture leg: alias-present tree asserts inferred:true course
cells + method recording + `course-name-join-open` absence; the
already-specified alias-absent legs assert the open-hole ledger.

Re-route "Owner/policy ruling whenever convenient" accordingly.

### F14 — MINOR — "NO additional or missing keys" vs conditional `axes`

§L3 freezes the row shape with no missing keys, then omits `axes` when
absent upstream. Pin `axes` as the single optional key so a strict
schema validator and the prose agree.

### F15 — MINOR — Residue class label misleads its stated consumers

entities that merely lack joins. §9 routes site IA (Q1 page-universe
decisions) to these very classes. Rename the residue
(`unclassified-residue`) or split a fifth class; data unchanged.
