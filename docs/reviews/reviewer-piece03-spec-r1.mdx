## Findings

Severity, location (spec line anchors), problem, fix shape.

### F1 — CRITICAL — preamble grounds a "dual-stated" reconciliation that does not exist (lines 16–22)

Problem: as audited above, "plot-label keys 139-not-136" and
"unlockables 60" are presented as disputes "resolved in favor of the
scout's on-disk re-measurements as dual-stated in revision 2", when
revision 2 carries only the scout's original figures with no verifier
variant and no re-measure anywhere. Two explicit verifyA REFUTED
verdicts are overridden without recorded evidence, and the spec's
charter sentence teaches every later reader (including the arbiter and
future revisions) that a reconciliation happened that didn't. Neither
figure is used by any contract below, so the fix is cheap — but the
sentence as written is untrue of the files it cites.

Fix shape: rewrite the preamble per-figure: state what r2 actually
carries; for 136/52 either adopt the verifier values into the
meta-record (noting this contract uses neither) or land a real on-disk
re-measure addendum in scout r2 first and cite that. Never write
"dual-stated" of a single-stated file. Optionally correct the r2 commit
message's overclaim in PROGRESS.mdx so the next reader isn't misled at
the same seam.

### F2 — MAJOR — `levels.jsonl` generation enum cannot represent 6 of its own 28 rows (M2, line 271 vs F4)

Problem: F4 splits the 28 `TPC.LevelConfig` dumps across FOUR config
families — `configs-levels-prefabs` 13, `configs_assets_all` 9,
`dlc-space-configs` 4, `dlc-ghost-configs` 2 — but the pinned enum is
`generation ∈ levels-prefabs | configs-assets-all`. The 6 DLC rows have
no representable value. With §8's "EXACT key sets; enums frozen"
validators, the real corpus fails validation on day one, or the
CodeWriter invents a third value off-contract. `variantOf` semantics
are likewise defined only for base pairs, leaving the Ghosts ×2 DLC
twins undefined.

Fix shape: widen the enum to the four measured config families (or pin
generation as bundle-family-derived with that closed vocabulary), and
define `variantOf` for DLC twin pairs (Ghosts 15×2).

### F3 — MAJOR — room `Tiles` and plot `TileTypes` bitmaps are promised homes that the housing schema cannot hold (M2 lines 316–319/346–349 vs M4 lines 481–489)

Problem: rooms.jsonl says "the occupancy bitmap rides `landscape_maps`
sidecars keyed `(scenarioName, uniqueId)`"; plots.jsonl says the
TileTypes bitmap "lives in `landscape_maps.jsonl`/`landscape_layers.jsonl`
keyed `(scenarioName, plotUniqueId)`". But M4's pinned landscape_maps
row is `{scenarioName, plotUniqueId, layerIndex, terrainMap,
landscapeObjectMap, attributeMap, buildId}` — keyed by plot layer, with
no room key and no slot for either bitmap. Per P6, plot `TileTypes` and
room `Tiles` are distinct payloads from the LandscapeRecord maps M4
carries. Net effect: the room occupancy bitmaps (5,188 rooms — the
entire room-footprint substrate of feasibility verdict V2) and the plot
tile bitmaps have NO home in the declared output set, and both
cross-references point somewhere that cannot take them. A builder
following the pointer either fails exact-key-set validation or silently
drops the geometry substrate this piece exists to ship.

Fix shape: give each bitmap family a named home — e.g. extend the M4
pair with a room-keyed sidecar (`rooms_tiles.jsonl` keyed
`(scenarioName, uniqueId)`, row-major verbatim) and an explicit slot for
plot TileTypes (inline in plots.jsonl or a plots_tiles sidecar), then
update §4's layout, AC2, and the §8 test legs to match. One home per
payload, no duplication — the spec's own rule.

### F4 — MAJOR — M7's reproducibility artifact doesn't pin its own predicates, and two pinned seeds contradict the cited verification (lines 626–646, F17 line 105)

Problem: M7 exists because "verification could not reproduce the
scout's selections from prose", yet the spec itself pins exact patterns
for only three of seven rows. `loadingscreen-images`,
`imagelevel-strict-prefix`, `imagelevel-family`, and
`level-image-icon-screenshot` name no pattern at all — the CodeWriter
invents them, reproducing exactly the failure the artifact was designed
to kill, and the TestWriter cannot blind-build expected counts. Worse,
of the pinned ones: the case-sensitive `/MetaMap/\|/Metamap/` predicate
is seeded at 1,094, but verifyA 10.2 measured that exact-case sweep at
**909** and found "no selection yielding 1,094"; the
level-image/icon/screenshot seed 125 is likewise unverifiable (42/66;
union 68). Shipping a knowingly-false seed as the headline count of a
pinned pattern repeats the fact-fidelity defect of F1 at artifact scale.

Fix shape: quote every predicate as a literal machine-checkable pattern
in this file (regex or exact substring/case rule), require
imagery_predicates.json to carry those strings verbatim beside fresh
counts, and annotate the two known-divergent seeds as DRIFT-expected
with the verifier's measured values alongside (909; 42/66).

### F5 — MAJOR — the R4/G6 arbiter route demands code-read evidence that nothing attaches and nobody owns producing (§7 row 1; ruling R4)

Problem: the PlotCount canonical-generation question routes to the
arbiter "with the required code-read evidence (`LevelConfig.LoadAssets`
— which generation instantiates at runtime)". No such evidence is
attached to the spec (no dump.cs citation, no quote — contrast F7,
which cites line numbers for every constant it relies on), and no seat
is assigned to produce it. As routed, the decision dead-ends: the
arbiter receives a requirement rather than an input, and the build pair
is explicitly forbidden from deciding it themselves.

Fix shape: either attach the LoadAssets code-read now (cite the
declaration and state which generation instantiates, in F7's citation
style), or assign its production explicitly — e.g. a named probe
artifact emitted by M1/M2 from the decompiled tree
(`maps/loadassets_read.json`), or a mandatory attachment in the arbiter
brief — with the orchestrator preference (pin the buildId-20226581
shipping generation, keep the other as `variantOf` history) as the
documented fallback if the read is inconclusive.

### F6 — MAJOR — the door HARD GATE is enforced only by an unpinned test-side grep; `instanceLinks` reads as a constant (M5 lines 573–583, AC11 lines 785–788)

Problem: the gate is the design's central safety property, but nothing
requires `stage7_maps.py` itself to refuse gated rows — enforcement
lives entirely in AC11's grep, whose detection rule ("rows asserting a
door→room-instance relation") is never defined mechanically, so a weak
TestWriter pattern produces false green. Sub-passes M6–M8 are clean
today, but nothing structural prevents a later sub-pass, revision, or
consumer path from leaking the edge once `door_id_space.json` exists to
be consulted. Additionally: `"instanceLinks": 0` is sketched as a bare
literal while every other seed in the spec is declared measured-with-
drift; and the gate wording ("NO artifact … may emit a
door→room-instance edge") over-reads onto `door_placement_index.jsonl`'s
`owningRoomId` column, which is placement containment, not validator-ref
gating — an ambiguity a literal-minded builder resolves by dropping a
column the spec requires.

Fix shape: (a) require an in-stage assertion on the emission path — any
row joining a validator id/ref to a room instance id fails unless
`reconciliation=="agreed" && instanceLinks>0`; (b) pin AC11's detection
rule concretely (e.g. no emitted artifact may contain both a validator
ref and a `rooms.jsonl` uniqueId in one relation row; type-gating edges
must carry `inferred:true, method:"roomtype-id-space"`); (c) declare
instanceLinks a measured seed (expected 0, drift-checked), matching the
house seed discipline; (d) scope the gate sentence to
validator-ref→room-instance edges, explicitly excluding placement
containment.

### F7 — MAJOR — `item_placements` identity tuple cannot uniquely identify the plotActivation family (M2 lines 374–389)

Problem: identity is pinned as `(scenarioName, recordFamily,
owningRoomId, itemIndex)`. But PlotActivationItemRecords ride per-plot
arrays inside `PlotRecords[i]` (P2), so `itemIndex` restarts per plot:
two plots' activation items collide on
`(scenario, plotActivation, null, itemIndex)`. On the real corpus this
either trips the uniqueness assertion (spurious exit 1) or forces the
composite `@r<recordIndex>` fallback to rename legitimate rows — and
the sort-by-identity contract is wrong for the family regardless. The
other four families are fine (owning rooms are unique per scenario by
the rooms identity rule; the non-room families are one array per
scenario).

Fix shape: extend the tuple with `plotUniqueId` for the plotActivation
family (or index items within their owning record), pinned per family,
with the §8 decomposition test updated to cover two plots carrying
activation arrays.

### F8 — MINOR — divergent seeds carried singly despite the preamble's "dual-stated" posture (F3, F11, M4, AC2, §8)

Problem: 4,070 plot layers (verifiers: 4,082 TerrainMaps; also a 0×0
dims minimum vs the seeded "min 2×2") and 55 door kinds (verifier: 56)
are kept scout-single although the cited verdicts measured different
values. Drift-wins makes them operationally harmless, but the F-lines'
"[A 3.x]" citations imply agreement, and AC2's "dims min 2×2" will
DRIFT on the first run for a reason the spec could have predicted.

Fix shape: dual-state known deltas at the F-line exactly as F12 does
for 13/71 ("scout X; verifier Y; reconcile at run time").

### F9 — MINOR — M1 rows lack the provenance AC5's complement demands (M1 lines 213–217 vs AC5 line 753–755)

Problem: `coordinate_law.json` worldBounds/spawnPoints rows are
positional leaves with no per-row `source{bundle, pathId}`, while AC5
fails any row whose "positional leaf lacks `source` provenance". The
stage's own acceptance criterion fails its own flagship artifact.

Fix shape: add `source` to M1 rows (the LevelConfig dumps are
(bundle, pathId)-addressable), or scope the complement explicitly to
the JSONL family files.

### F10 — MINOR — M3 cross-file resolution omits piece-2's cab-underdetermination discipline (M3 step 2b, lines 430–433)

Problem: the ladder terminates at "`externals.jsonl` →
`cab_index.jsonl` → `(bundle, pathId)` → index". Piece-02 R2 pinned
`dstCab` precisely because Unity pathIds are per-serialized-file and
bundles carry several (222 files across 176 bundles), so
`(bundle, pathId)` alone under-determines a target. The 771 expected
cross-file resolutions may be ambiguous or mis-attributed without the
CAB leg, and `_unresolved_placements.jsonl` rows carry no
extFileId/dstCab evidence to debug misses.

Fix shape: inherit the piece-2 rule end-to-end — resolve through the
CAB, carry `extFileId`/`dstCab` in resolution evidence and in the
unresolved-ledger row shape.

### F11 — MINOR — example rows embed unverified leaves next to EXACT-key-set validation (M1/M2/M5 sketches)

Problem: illustrative rows contain values nothing measures —
plots `layerCount: 4`; source-bundle spellings like
`dlc-space-configs_assets_all.bundle` /
`configs-levels-prefabs_assets_all.bundle`; scenarios root keys
`ScenarioName`/`Version`/`NextPlotUniqueId`; the door-validator message
fields. None appears in scout r2 or the P-probes. Combined with §8's
EXACT-key-set schema tests, these can bake into fixtures as
pseudo-contract, and a real dump missing a "required" message field
fails validation.

Fix shape: stamp every example block non-normative ("illustrative
shape; every leaf re-measured at run time"), and either probe-verify
the door-validator field list or mark the message fields optional in
the emitter contract.

### F12 — MINOR — plots/rooms drop the `Definition` PPtr that placements keep (M2 lines 296–313/326–341 vs P2/P3)

Problem: `PlotRecords[i]` and `RoomRecords[i]` carry a `Definition`
PPtr (P2/P3), but the emitted rows keep only `definitionId` +
`definitionPathId: null` — unlike item placements, which carry the full
`definitionPptr`. The substrate loses the joinable pointer for
plot/room definitions (resolvable later to FloorArea/PlotDefinition
dumps), against Principle zero and the piece's own substrate mandate.

Fix shape: emit `definitionPptr {fileId, pathId}` for plots and rooms
exactly as placements do, or add an `_absences.jsonl` row naming the
omission deliberately.

### F13 — MINOR — client-gated lane never exercises the levels↔scenario GUID chain (§8 client-gated list)

Problem: `levels.jsonl` ships `scenarioGuid`/`scenarioAddress`/
`campaignPart` (derived per M2), and F4/A4.5 measure 27-of-28 GUID

green.

Fix shape: add a client-gated leg: ≥27 of 28 `scenarioGuid`s resolve to
catalog addresses; `campaignPart` on resolved rows matches the Part*
path segment; blank template row carries nulls.
