## 5. Relinking floor — doctrine bar #3 ([DR-2026-08-17-relink])

**On a planned path, not yet a demonstrated one — single point of failure.**
All four candidate models were unreachable by curl; only Steam Community
guides is confirmed alive (HTTP 200 shell, guide list not server-rendered
in that URL shape). The planned unlock — ABP-browser passes during the
competitor-research phase — is plausible but unproven against
challenge-page walls, and AGENTS rule 10 forbids retrying into challenges.
A failed ABP pass strands the floor at 1-of-3 sources, and bar #3 is
unconditional: walls are an access fact, not a waiver.

The spec MUST schedule:

1. **ABP-browser analysis passes** per walled source during
   competitor-research, walls re-recorded as findings (§6 already
   promises this).
2. **A named fallback ladder now**, before ABP is proven — e.g. web-archive
   snapshots of the fandom/wiki.gg entity pages, the Steam guides corpus
   via alternate/paginated endpoints, the gaming.tools inventory
   (site-sections tool-discovery step 1 doubles as a source), official
   publisher/studio resources. Without a pre-named ladder the floor has
   no exit if the browser hits the same walls.
3. **The APPLY artifacts.** Bar #3 fails on "lists sources without
   extracting and applying their relationship model." §6 correctly
   refuses to merely record; the spec must give the delta a destination —
   added joins / derived edges landing in `extracted/relinks/` +
   `RELATIONS.md` as a concrete pipeline stage, with repo-only provenance
   per AGENTS rule 3 (source identity never reaches user surfaces).

Credibility overall: the *target selection* is sound (two independent
wiki instances of the same relationship model + a player-authored chain
corpus + reserves). What is missing is only the schedule above.
