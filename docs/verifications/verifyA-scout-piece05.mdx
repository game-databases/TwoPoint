## M1 — G1 mechanism (what the pin stage should encode)

- Counter side: `- <locale>: rows=` prints `evidence["rowsEmitted"]`
  (`tools/stage4_localisation.py`, run-section emitter ~line 492), which
  is incremented once per successful term **write** — including writes
  that overwrite a previously-seen key. The overwrite branch even
  tallies its own counter (`duplicateKeysOverwritten`), but that counter
  is **never printed** to the run section, which is why the drift was
  invisible.
- Artifact side: `log_util.write_jsonl(path, [{"id": k, "text":
  rows[k]} for k in sorted(rows)])` — one line per **distinct** key.
- Therefore `logged − disk = duplicate-key overwrites for that locale`.
  All 13 locales show +5 ⇒ the shared I2 sources contain exactly 5
  duplicated Term keys (same sources decoded per language, so the dupes
  repeat per locale). Arithmetic identity holding on every line:
  `rowsLogged = 15,677 termsWalked − skippedEmpty` (skippedAbsent = 0).
- In-run corroboration that both units coexist in one section:
  `baseOverlayRows: 15672` (len of dict) beside `BASE-OVERLAY:
  rows=15677` (writes); `englishRowCount: 15665` beside `en:
  rows=15670`.
- Not verifiable locally: naming the 5 duplicated keys (requires
  re-decoding locale bundles on NE8K). The delta + code path already pin
  the mechanism; the pin should either make the counter count distinct
  keys or print `duplicateKeysOverwritten` beside it.
