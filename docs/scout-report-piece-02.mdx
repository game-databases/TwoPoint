### Cells with no measured surface today

All unlisted off-diagonal cells read **none-yet or needs-probe**, not
absent-by-proof. The two structural reasons:

1. **Cross-file PPtrs (23,250 refs)** hide any pair whose references
   cross serialized files inside a bundle — the most likely carrier for
   e.g. `item→student-type` (validators), `course→room` direct edges,
   and unlock-tree chains. Unblock: stage 3 emits per-dump external
   file tables (file-id → bundle/pathId), then the same resolution
   pass re-runs unchanged.
2. **Kind taxonomy is coarse.** The `config` kind is 339 classes;
   `unlockable` is 48. Definition classes land under kinds that don't
   match their domain name (`TPC.CourseModuleDefinition` → `config`,
   not `course`). The matrix skeleton should therefore be published
   **per class-family inside each pair cell** (the class-level join
   table above), not just per kind.

## §2 The GUID→locale mechanism — hypothesis REFUTED, real mechanism MEASURED

Stage 5 measured zero string joins because it scanned for payload
strings equal to matrix keys. The game does not do that. Measured
mechanism, end to end:

1. **Entity side.** Localizable fields are embedded structs
   `TPS.Core.Localisation.LocalisedString = {_dev: string, _termID:
   int32}` (dump.cs TypeDefIndex 9108; verified in payloads, e.g.
   `staff/Staff_Assistant.LocalisedName = {"_dev": "Assistant",
   "_termID": -744531364}`). No GUID-shaped value participates anywhere
   in locale joining — **the localization-GUID hypothesis is refuted**;
   the join key is a signed 32-bit term ID.
2. **Registry side.** 26 `I2.Loc.LanguageSourceAsset` dumps
   (bundle `localisation_assets_localisation.bundle`) each carry
   `mSource.mTerms[]` rows `{ID: int, Term: string, TermType,
   TermStatus, Languages[13], Flags[13]}` — measured on dump
   `I2LS_General`: term `General/Achievements/AllLevels_Description`,
   ID `-1672347010`. Code confirms the runtime map:
   `LanguageSourceData.mDictionaryID: Dictionary<int, TermData>` +
   `GetTermData(int termID)` (dump.cs lines ~546727, ~546893).
3. **Measured overlap (this session's decisive probe).** Building the
   ID→Term registry from all 26 sources yields 15,677 term rows →
   15,675 distinct IDs → **15,672 distinct Term keys, which equals the
   locale-matrix key set exactly (bidirectional diff 0)**. Scanning all
   12,764 stub payloads finds 19,272 `LocalisedString` instances:
   - **10,480 instances (54.4%) carry a termID present in the registry;
     every one of those resolves to a key inside the locale matrix
     (10,480/10,480).**
   - 8,788 instances carry sentinel `_termID: 0` (unlocalized /
     dev-text-only, empty `_dev`) — not misses.
   - Exactly 4 instances carry non-zero IDs absent from the registry
     (`-1168948158` "Cancel Upgrade", `-2044546668` "Requires Janitor
     with Mechanics", `-1942168175` "Unassigned", `-1451566921`
     "Wants a {ITEM}" — the latter on `Unused_PersonalGoal_Item_Gym_Vaulting_Horse`),
     plus 3 term keys registered under two numeric IDs each. Effective
     coverage on non-empty localised strings: **10,480/10,484 = 99.96%.**

Per-kind instance counts and hit rates (probe artifact
`../_scout2_locale_join_perkind.json` regenerated inline; headline
numbers): configs 6,665/11,888 hits; items 2,736/6,030; rooms 438/521;
metagame-nodes 390/553; unlockables 69/98; courses, staff,
student-types **100%** (41, 33, 108); campus-levels 0 localised fields.

Consequences for the relink layer:

- The entity↔locale relation family is **hard** (`inferred: false`),
  mechanism = `int-termID → I2 registry ID → Term key → locale-matrix
  key`, cardinality N:1 per field. It must be derived as
  `relinks/entity_locale.jsonl` (+ reverse index) by a later piece; the
  registry itself should be emitted as a first-class artifact
  (`relinks/i2_term_registry.jsonl`: termID, termKey, source asset,
  termStatus, flags) since stage 4 currently emits only key→text rows
  and drops `TermData.ID`.
- `IconReference`-style `{m_AssetGUID, m_SubObjectName}` fields are a
  separate, art-side join: 20,042 GUID refs across stubs, 5,548
  distinct GUIDs, **15,982 (79.7%) resolve to catalog addresses** via
  the `guid`-kind keys in `addressables/catalog.json` (54,143 guid
  rows; e.g. staff icon GUID →
  `Assets/Data/UI/Textures/Atlases/UI_Icons.spriteatlasv2`). 1,137
  distinct GUIDs dangle (ledgered §6). This is entity→asset, not
  entity→locale.

## §3 Cross-bundle identity & axes provenance

Measured facts (R10 duplicate policy output, stage-5 log + disk):

- Emitted id space is collision-free per kind (e.g. configs: 7,756
  rows = 7,756 distinct ids).
- Raw duplication events: **21 identical-payload merges** and **22
  disambiguations** (differing payloads → `<id>@<contentHash8>` twins,
  bare twin retained for 13 of 15 config twins). All merges observed so
  far are intra-axis `base` (e.g. `HBAOPostProcess` carrier in
  `configs-metagame_assets_all.bundle` with `axes:["base"]` vs its
  differing twin `@eee7f342` in `configs_assets_all.bundle`).
- Axis enum is filename-derived (`tpc_common.axis_for_bundle_name`):
  `base | dlc-space | dlc-ghost`. **No verbatim id exists in more than
  one axis after policy application** — DLC content partitions cleanly
  at the id level (DLC entities carry `DLC1`/`DLC2` name segments).

Recommendation for how axes-provenance surfaces in relations:

1. Every emitted relation row carries `sourceAxes: [...]` inherited
   from its endpoint rows' `axes` when present, plus per-endpoint
   `bundle` provenance already in stub `source`. Today only 2 rows on
   disk carry `axes` — the merged-carrier population is tiny but the
   schema slot exists and should be propagated, not reinvented.
2. Relation resolution must treat `@hash` twins as **distinct
   definition versions of one logical entity**: group by verbatim id
   (preserved in `fields.id`), expose `variantOf` semantics, never
   collapse silently. 13 bare-twin pairs in configs are the working
   example.
3. Cross-axis identity collisions being zero means axis-scoped pages
   can key on verbatim ids without disambiguation — but the invariant
   belongs in a test, not an assumption (a future DLC patch can break
   it).
