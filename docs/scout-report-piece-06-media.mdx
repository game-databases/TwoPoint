Findings that shape the piece:

1. **Every icon-bearing field resolves to a SpriteAtlas asset, 100%.**
   All 3,870 sprite-typed references land on `.spriteatlasv2` assets
   (`UI_Icons`, `UI_Items_New`, `UI_Costumisation`, `UI_StatusIcons_New`,
   `DLC1_Space_UI_Icons`, `DLC2_Atlas_*`, …) with the concrete sprite in
   `m_SubObjectName`. Zero dangling among genuine icon fields — the only
   dangling icon-shaped field in the whole corpus is
   `EditorFallbackIconReference` (351, editor-only GUIDs absent from the
   runtime catalog; ledger and skip).
2. **Distinct referenced sprites: 2,158; resolved: 2,151 (99.7%).**
   The 7 unmatched are all DLC3/Medical-School-named
   (`UI_InGame_DLC3_Icon_studentArchetype_Doctors`,
   `UI_InGame_T_Icon_Item_Teamsports_Cheeseball`, …) — content of the
   unowned DLC 2195430, consistent with catalog-coverage's 19
   out-of-roster `dlc-hospital-*` references. Honest missing states,
   not defects.
3. **PPtr icon fields are dead weight**: `ItemsMenuIcon` /
   `SwatchMenuIcon` plain PPtr slots measure `m_PathID=0` (null) on the
   sampled rows while the paired `*Reference` GUID fields carry the
   data — the Reference pattern IS the icon mechanism. Export stage
   ignores bare PPtr icon slots (matches piece-02's slug-null finding).
4. **Measured icon sizes for the referenced set** (rects matched by
   name against the sweep): median max-dim **42 px**; ≤64 px 1,509
   (70%) · ≤128 px 1,813 (84%) · ≤256 px 2,039 (95%) · >512 px 41.
   Total source crop area **26,595,109 px** ≈ 101 MiB RGBA-equivalent.
5. **courses are the hole.** `TPC.CourseDefinition` carries no icon or
   visual reference field at all. Name-convention matching
   (`Course_X → UI_InGame_Courses_T_Icon_X`) resolves only **11/69**;
   42 `*_Courses_T_Icon_*` sprites exist. The real carrier is likely the
   Qualification PPtr chain or configs-side course art (§9 Q1).

Page topology, measured: atlas pages are named
`sactx-{page}-{W}x{H}-{format}-{AtlasName}-{hash}` — largest pages are
**4096×4096 DXT5** (`UI_Items_New` has ≥3 pages + a 4096×2048 tail;
`UI_Icons` 4096×4096 + 2048×4096; `UI_Costumisation` two 4096²).
Pages serialize with byte_size≈0 (pixels streamed from bundle blocks).

Grid layouts: **not grids.** Sprites carry individual packed rects
(`textureRect` x/y/w/h, e.g. `UI_Generic_T_Spritesheet_…_Tabs_Main_DLC`
70×70 @ (227,31)); padding bleeds are visible in rect offsets
(±6.07 px on trimmed sprites). There is no measurable uniform cell size
to exploit — the export must crop by per-sprite rect, which the probe
shows is fully available. `m_IsVariant=false` on all inspected atlases;
3,154 packed slots vs 6,789 catalogue Sprites ⇒ ~55% of sprites live
outside atlases (standalone `ui-art-icons` 256×256 sheets etc.) — the
exporter needs both routes (crop-from-page AND standalone-texture
pass-through).

## §5 Web-export requirement spec inputs (formats/ladder/naming/provenance)

Inputs the Documentator should pin — each traced to a §2–§4 measurement:

- **Formats.** Primary **WebP** (lossy q≈80 + alpha for icons; lossless
  acceptable alternative — Pillow 12.3.0 WebP support verified in the
  pack venv this session, `features.check('webp')=True`). PNG as the
  zero-surprise fallback for ≤64 px flat glyphs if WebP artifacts show.
  **AVIF NOT-NOW**: no `pillow-avif-plugin` in the venv (checked);
  ffmpeg 7.1 exists on PATH as an emergency transcoder but adds a
  second encode stack for no measured benefit at icon sizes.
- **Ladder.** Ship ONE canonical asset per sprite at native resolution —
  median max-dim 42 px, 84% ≤128 px (§3.4); downscaling 42 px sources
  to a fixed 16/32/64 ladder destroys them, upscaling lies. Optional
  secondary: cap >512 px outliers (41 sprites, mostly screenshots)
  at 512. CSS owns presentation sizing. No @2x tier (sources ARE the
  native resolution).
- **Naming.** `{plane}/{subObjectName}.webp` where subObjectName is the
  game-canonical sprite name (unique enough: 2,158 referenced names,
  collisions handled by `{name}_{pathId}` suffix rule — same rule as
  stage-3 dump filenames). **Entity-slug naming is a LATER pure rename
  map, not the export key**: piece-02 proved slug fields 100% null and
  prefix-strip resolves 1/417, so slugs do not exist yet; blocking the
  media stage on slug generation would invert the dependency. Emit
  `media/index.jsonl` mapping `(kind, srcId, fieldPath) → subObjectName
  → file` so the frontend never hardcodes either key.
- **Provenance per exported asset (repo/data plane only** — AGENTS rule
  3 two-class rule; never user-facing): `buildId 20226581`, source
  bundle, sprite pathId + atlas page pathId, assetGUID, subObjectName,
  contentAxis (base/dlc-space/dlc-ghost), output sha256, encoder+
  version pin. User surfaces carry buildId + coverage scope only.
- **Determinism contract** (matches house stage discipline): inputs =
  `media-catalogue.jsonl`, `relinks/entity_asset_guid.jsonl`,
  `relinks/bridges/container_index.jsonl`,
  `addressables/catalog.json`; outputs = `extracted/media/{icons,…}/**`
  + `media/export-manifest.jsonl` + sha256 hash manifest; idempotent
  re-run byte-stable (fixed Pillow/WebP version pinned in
  EXTRACTION-LOG.md); missing-icon refs land in an exit-2 ledger
  (`_missing_icons.jsonl`: the 7 DLC3 names + anything newly dangling)
  rather than failing the stage.
- **Out of scope for this piece** (per [DR-2026-08-18-media-scope] and
  promptForDB #5): audio/video (carve-out), meshes/animations
  (catalogue-first), fonts, generative/site-chrome art (later #44
  imagegen pass — this piece is CLIENT-owned art only).
