## 1. Goal

ONE discoverable entrypoint at the TwoPoint pack root reproduces the
**harvest → decompile → relink-ready raw layers** from the game install:

```
A:\SteamLibrary\steamapps\common\Two Point Campus
```

…per [DR-2026-08-18-pipeline] and the extraction doctrine's Principle
two. Concretely:

- `run_all.py` (real entrypoint) + thin `Makefile` wrapper
  (`make setup|extract|stage|list|help`), mirroring the proven
  against-the-storm shape.
- `python run_all.py <game-path>` runs every stage in order;
  `--only <stage>` runs one stage in isolation; `--list` enumerates
  stages; `--force` ignores up-to-date stamps; `--skip a,b` skips.
- Every stage is **idempotent** (re-running yields byte-identical
  declared outputs) and **individually runnable**.
- Defaults (tool paths, versions, buildid) are read from the
  `<!-- stage-defaults-begin/end -->` JSON block in
  `extracted/EXTRACTION-LOG.md`, with embedded fallback pins — the log
  is the source of truth per doctrine; the entrypoint updates it in the
  same commit that changes tooling. Embedded fallback pins include the
  UnityPy version (`1.25.3` — newest precedent recorded in
  toolchain.md); `make setup` installs the pinned version into the pack
  `.venv`.
- Hardcodes no machine paths: game dir passed as argument (install root
  or `TPC_Data` auto-detected), pack dir derived from `__file__`,
  env overrides `TPC_GAME_DIR` / `TPC_PACK_DIR` /
  `TPC_EXTRACTED_ROOT` (redirects the extraction root away from
  `<pack>/extracted/` — tens-of-GB writes prefer D:/A: per toolchain.md
  host realities; every `extracted/…` path in this spec is relative to
  the resolved root). The make surface's `GAME=` is the same knob
  spelled for make: `make extract GAME=<path>` exports
  `TPC_GAME_DIR=<path>` before invoking the entrypoint — two spellings,
  one variable.
- Console discipline: force UTF-8 stdout/stderr (Windows cp1252 crash
  lesson); all file writes explicit `encoding="utf-8"` and
  `newline="\n"`.

Piece 1 delivers the **raw layers** (stages 0–5 below). Logic
derivation, the pairwise relink matrix, map geometry, and PROOF
reconciliation are later pieces consuming the directory contracts this
piece fixes (§6).

## 3. Stages

### Stage 0 — `verify-client`

**Purpose:** pin identity, gate the dumper choice, emit the bundle
roster as the pipeline's first artifact (verifyB 1.2).

- **Script:** `tools/stage0_verify_client.py`
- **Inputs:** game root (auto-detect: root carrying `GameAssembly.dll`
  + a `TPC_Data` child with `il2cpp_data/Metadata/global-metadata.dat`
  and `StreamingAssets/aa/`); `appmanifest_1649080.acf` discovered by
  walking up ≤4 levels (steamapps dir); `version.txt`;
  `globalgamemanagers` (Unity ASCII version near offset 0x30);
  directory listings of `aa/StandaloneWindows64/`, `DLCs/space/`,
  `DLCs/ghost/`.
- **Steps:** read manifest (`buildid`, `TargetBuildID`, `language`);
  read version.txt; read Unity version; read metadata sanity+version;
  **metadata-version gate:** version `< 38` → dumper =
  `il2cppdumper` (primary per toolchain.md decision); `>= 38` → exit 3
  with the Cpp2IL escalation message (KB wall; do NOT attempt);
  enumerate every `*.bundle` under the three dirs with byte sizes and
  classification flags.
- **Outputs:**
  - `extracted/identity.json` — `{appid, buildId, targetBuildId,
    versionString, unityVersion, metadataVersion, dumper,
    addressablesVersion, settingsHash, languageSetting,
    expectedBundles:{aa:158,"dlc-space":10,"dlc-ghost":8},
    localeBundleCount:14, sceneCounts:{strictUnityBase:21,
    seasonalSceneCarryingBase:22, strictUnityInstall:25,
    sceneCarryingInstall:26}}`
  - `extracted/bundle-roster.jsonl` — one row per bundle:
    `{relpath, dirClass: base|dlc-space|dlc-ghost, bytes,
    sceneFlag: none|.unity|seasonal-scenes, localeFlag: null|base|<bundle-lang>,
    buildId}` sorted by `relpath` (determinism).
  - seeds `extracted/EXTRACTION-LOG.md` (header pins +
    stage-defaults block, incl. the UnityPy version pin — embedded
    fallback `1.25.3`) if absent.
- **Acceptance:** exits 0 iff all inputs found and readable;
  `TargetBuildID == buildid` (warn-only on mismatch — a patched install
  must still run); roster row count == enumerated `*.bundle` count;
  exactly 14 `localeFlag != null` rows; live counts differing from
  `expectedBundles` print a `DRIFT:` warning line (never a failure —
  drift detection, not a gate); second consecutive run byte-identical.

### Stage 2 — `harvest-catalog`

**Purpose:** decode the Addressables catalog into the full
key → bundle/address index — the backbone of every later join.

- **Script:** `tools/stage2_harvest_catalog.py`
- **Inputs:** `aa/catalog.bundle` (1,704,718 B), `aa/settings.json`,
  roster from stage 0. Measured shape (Revision 4): the bundle carries
  NO MonoBehaviour — the payload is a single TextAsset named `"catalog"`
  holding ~11.7 MB of JSON with `m_LocatorId`
  ("AddressablesMainContentCatalog") plus base64-encoded binary blobs
  `m_KeyDataString` / `m_BucketDataString` / `m_EntryDataString`.
  **Primary decode:** open the bundle with UnityPy, take that
  TextAsset, parse its JSON, and decode the three data strings per the
  Addressables 1.21.x layout — as far as needed to resolve keys →
  owning-bundle references. The MonoBehaviour/typetree route (stage 1
  dummy DLLs + TypeTreeGeneratorAPI) is the SECONDARY/absent path,
  probed only when the TextAsset is missing or malformed — never the
  primary. The OUTPUT contract below is fixed regardless.
- **Outputs:**
  - `extracted/addressables/catalog.json` — `{meta:{buildId,
    addressablesVersion:"1.21.10", settingsHash, providerIds[]},
    keys:[{key, kind, bundle, address, dependencies[], providerIds[]}]}`
    sorted by `key` (determinism). Full index: every addressable key
    with its owning bundle and internal address.
  - `extracted/addressables/settings.snapshot.json` — verbatim copy of
    `settings.json` + parsed subset for machine readers.
  - `extracted/addressables/catalog-coverage.json` — `{keysTotal,
    distinctBundlesReferenced, bundlesUnreferenced:[…]}`. Universes

### Stage 5 — `emit-stub-datasets`

**Purpose:** canonical JSONL skeletons per entity family from the
MonoBehaviour/ScriptableObject dumps — **rows land contract-pinned even
where fields are only partially understood** (owner rule: stub data in
place rather than absent).

- **Script:** `tools/stage5_emit_stubs.py`
- **Inputs:** `harvest/monobehaviours/**`, `addressables/catalog.json`,
  `decompiled/structural/*`, `locales/locale-matrix.json`.
- **Entity identity policy (Revision 6):** applied before any row is
  emitted; every rule's decisions are counted in the run section.
  1. **COMPONENT EXCLUSION** — only entity-bearing scriptable
     definitions are candidates: a MonoBehaviour whose script class
     resolves into the game's config/definition hierarchy qualifies.
     Engine/primitive components (Transform, Collider, Renderer,
     MonoBehaviour-without-resolved-script, `Interaction*`, …) NEVER
     become entity rows. The resolved `_scriptClass` (post
     typetree/synthesis fix) is the discriminator; unresolved-generic
     dumps are census rows, not entities.
  2. **ID RESOLUTION** — a row without a resolvable verbatim identifier
     is NOT emitted as an entity (`id=''` swept in en masse on the
     measured run: rooms 156/156, student-types 33/33,
     items 8,829/8,896); it lands in `_absences.jsonl` (counted,
     sampled), never silently and never as a stub row.
  3. **DUPLICATE POLICY** — within a family, identical-id rows whose
     full payload hashes EQUAL merge into ONE row carrying an
     `axes:[base|dlc-space|dlc-ghost]` provenance list naming every
     content axis that contributed (legitimate cross-bundle definition
     copies measured: `Bloom` ×24; `Config_DLC1`/`Config_DLC2` mirror
     base configs per DLC axis); identical-id rows with DIFFERING
     payloads stay DISTINCT via the deterministic composite suffix
     `@<contentHash8>` on the emitted `id`, the original verbatim id
     preserved inside `fields` (Principle one holds — the suffix is
     additive, nothing is renamed away). Counters: `mergedDuplicates`,
     `disambiguatedDuplicates`.
  4. **POST-POLICY UNIQUENESS** — per-family schema uniqueness is
     asserted after exclusion + merge/disambiguation, never over raw
     sweep order.
- **Outputs:** `extracted/stubs/<kind>.jsonl` for the seeded families —
  kind names match spec.md `entities`; the kind VALUE ↔ FILENAME map is
  pinned exactly (the schema validator depends on it):

  | kind value | file | kind value | file |
  |---|---|---|---|
  | `item` | `items.jsonl` | `unlockable` | `unlockables.jsonl` |
  | `room` | `rooms.jsonl` | `campus-level` | `campus-levels.jsonl` |
  | `course` | `courses.jsonl` | `config` | `configs.jsonl` |
  | `staff` | `staff.jsonl` | `metagame-node` | `metagame-nodes.jsonl` |
  | `student-type` | `student-types.jsonl` | | |

  Row shape (pinned contract):
  ```json
  {"id":"<verbatim internal id>","kind":"item","slug":null,
   "fields":{"…understood subset, raw values, identifiers untouched…"},
   "source":{"bundle":"items-general_assets_all.bundle","pathId":123,
             "class":"ItemConfig"},
   "provisional":true,"inferred":true,
   "method":"seeded-family-heuristic","buildId":20226581}
  ```
  Provenance flags pinned (data-acquisition.md provenance rule): ids,
  GUIDs, path_ids, loc keys and RAW FIELD VALUES copied from dumps are
  HARD-READ — always verbatim, guarded by the byte-match test, never
  flagged `inferred`. The `inferred` flag + `method` string carry the
  DERIVED planes only: seeded-kind assignment (`inferred:true` +
  `method`; flips to `false` only when an explicit in-dump discriminator
  fixes the kind) and any convention-derived association
  (`inferred:true` + method naming the convention).
  A family with no identifiable rows after scanning gets a row in
  `extracted/stubs/_absences.jsonl`: `{kind, scannedBundles:[],
  scannedClasses:[], evidence:"why nothing matched"}` — ledgered
  absence, never silence. Symmetrically, every harvested MonoBehaviour
  class/family with NO seeded kind gets a row in
  `extracted/stubs/_unmapped-families.jsonl`:
  `{class, bundles[], objectCount, evidence:"no seeded kind covers this
  class"}` (empty file valid iff nothing was unmapped) —
  discovered-but-unmapped content is never silent either.

  This stage is the **SOLE OWNER** of
  `extracted/relinks/locale_availability.jsonl`: entity-granular
  (localization-architecture §5.4-complete), REGENERATED ON EVERY
  stage-5 run — which satisfies §5.4's rerun clause with no second
  writer. Row shape: `{kind, id, availableLocales[], namedLocales[],
  fieldPresence:{<locale>:[<joined fields present>]}, joinInferred,
  joinMethod, buildId}`. Entity→loc-key JOIN PROCEDURE (pinned,
  deterministic — real field names stay unknown until stage 3 opens the
  bundles, so the procedure is the contract):
  1. collect the entity dump's string-valued fields;
  2. a field whose value EXACTLY equals a `locale-matrix.json` key
     joins HARD (`joinInferred:false`);
  3. a field matching a loc-key convention shape (e.g. an
     `<entityId>_<role>` pattern) joins `joinInferred:true` +
     `joinMethod` recording the convention applied;
  4. no other association path exists.
- **Acceptance:** exits 0; for EVERY seeded family: non-empty
  `<kind>.jsonl` XOR `_absences.jsonl` row naming scan scope; filenames
  conform to the pinned kind↔file map; every row passes schema check
  (required fields present, types correct); identifier preservation
  test — ALL `id`s byte-match their source dump values when a family
  has ≤1,000 rows, else a deterministic sorted sample of 500;
  `buildId == identity.buildId` on 100% of rows; every harvested
  MonoBehaviour class either maps to a seeded kind or has an
  `_unmapped-families.jsonl` row; `locale_availability.jsonl` is
  regenerated on every run, its row count == distinct joined entities,
  and every row carries `availableLocales` + `namedLocales` +
  `fieldPresence`; rerun byte-identical.
