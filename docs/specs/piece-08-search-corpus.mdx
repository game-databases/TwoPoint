## 1. Goal

ONE additive entrypoint stage turns the verified entity/locale corpus
into the search data layer FRAMEWORK [§2.9](../../FRAMEWORK.md) requires
— a pipeline-owned index artifact, derived, disposable, and rebuilt
from committed inputs:

- New stage id **`search-corpus`**, script
  `tools/stage12_search_corpus.py`, registered ADDITIVELY in
  `tools/tpc_common.py::STAGES` LAST in the enumeration. Every existing
  stage byte-behaves identically.
- **Purely derived stage:** it opens NO bundles, imports NO UnityPy,
  and needs NO game dir. Its entire upstream set is committed
  `extracted/` artifacts plus two optional DATA input files (§4
  Inputs). Consequences: it runs hostless on the real corpus, the media
  carve-out guard cannot regress, and the fixture tree covers it
  without synthetic Unity bytes.
- **Emission root `extracted/search/`:**
  - **13 per-locale document shards** `shards/<locale>.jsonl` — one
    document per searchable entity present in that locale (pre-ruling:
    per-locale shards are MANDATORY; option A's combined lang-tagged
    index is rejected because every route-coded locale would ship
    everything).
  - **13 titles-only projections** `titles/<locale>.jsonl` — the slim
    hydration plane the shell loads for the instant box (option C's
    two-plane split, shipped rather than deferred).
  - **One hash manifest** `manifest.json` (sha256 per shard + universe,
    analyzer, alias, collision, sizing, and rebuild-provenance blocks)
    and `hashes.json` over every emitted file.
- **Carrier-definition-explicit universe:** the conservative variant
  (**7,178**) and the expanded planning floor (**10,200** = 75.9 %)
  are BOTH computed every run from pinned component recipes, the delta
  DRIFT-tracked (§S1). The index plans against the expanded floor.
- **Alias layer:** course-name resolution encoded as three mechanical
  families + normalization rules + a 7-entry token map + a CURATED DATA
  INPUT FILE seeded with the residual rows (§S3); collision handling
  preserves the measured many-to-many truth (264 colliding title
  pairs, "Lab Work" ×53) instead of inverting text→entity.
- **Tokenization:** per-locale analyzer configuration shipped IN the
  manifest — whitespace standardizers for ten locales including ko,
  char-bigram for zh-Hans/zh-Hant, mixed strategy for ja — with
  measured vocab stats embedded so the client can budget edit-distance-2
  typo tolerance (feasible at the measured 11.9k–28.6k vocab; no
  Algolia-class infra).
- **Determinism:** byte-stable reruns, hash manifests, temp+rename
  write discipline, and the piece-1 exit-code contract extended with
  the PRECISE relink-exit-2 discrimination rule of §S5 (tolerate the
  declared steady state; never mask a real relink regression).

Everything else — ranking implementation, MiniSearch instantiation,
UI, hosted search infrastructure, guide/news corpus — stays out (§7).

## 3. Competitor search bar + product constraints the index serves

Measured live by the scout (§5) and re-verified token-for-token by vB
attack A4 (one attempt per walled surface, AGENTS rule 10):

- **new-world.guide — the instant-UX floor:** Algolia instantsearch.js
  **4.48.0**, lazy-loaded (chunk `2603-23dd55c8c80ad584.js`, 113,820 B,
  version string verified; absent from home critical path); hosted-SaaS
  results-as-you-type with built-in typo tolerance + facet filters;
  i18n keys `search_items` / `search_string` /
  `searching_items_includes` / `search_perks` / `search_not_found`;
  **single-locale** (`lang="en-US"`, zero hreflang).
- **wikily.gg — per-game scoped, search surface unobservable:** Next.js
  RSC; header "Search" label; `/search` → 308 → `/search/` → **404**
  (per-game `/ark-survival-ascended/search/` also 404); no
  algolia/typesense/meilisearch/lunr/minisearch/flexsearch hit in
  landing HTML + 16 chunks. (Its PAGE grid routes 24 hreflang locales —
  piece-07 §3 — but no per-locale SEARCH mechanics are observable.)
- **metaforge.app — walled** (403 ×2 incl. the authorized crawler-UA
  retry; stopped per rule 10). Question it would have answered: whether
  planner/search is a client-side instant filter and any per-locale
  routing.

**Floor statement for this piece:** competitors demonstrate instant
type-ahead over entity names and kind-scoped filtering; NEITHER
demonstrates per-locale entity search on any observable surface. Our
**13-locale routed search** — shards keyed to the route-coded locale
paths of [DR-2026-08-20-locale-urls], pivot `en` at the bare path — is
the differentiator, and it is cheap at our scale (F16/F17: single-digit
MB per locale plane, zero hosted infra). Design constraints the artifact
must therefore protect:

1. **Never let an en-only index become the primary surface** for a
   non-pivot route; every locale route hydrates its own shard.
2. **Instant filtering is the interaction law**
   ([DR-2026-08-22-search-is-not-a-page],
   [DR-2026-08-22-inputs-answer-as-you-type]): a header field, results
   replace page content in place from two characters, no submit control.
   Document shards + client-side MiniSearch instantiation satisfy this
   at ≤10.2k docs/locale; the DATA layer ships documents + analyzer
   config, never a library-coupled prebuilt index.
3. **Typo tolerance budget is a shipped fact, not hope:** the manifest
   embeds per-locale vocab stats; worst case 28,594 terms makes client
   Levenshtein-d≤2 (BK-tree/SymSpell) feasible — the manifest states it
   (`typoBudget`), the client implements it.
4. **Many-to-many honesty:** 264 colliding (kind,title) pairs mean
   text→entity inversion is forbidden architecture; documents stay
   keyed by entity, ranking hints ride the manifest (kindWeights), id
   disambiguation is always available.

### S2 — Per-locale document shards

One document per (searchable entity, locale) — the record carries the
entity's whole searchable surface for that locale.

Frozen row shape (exact key set; NO additional or missing keys):

```json
{"kind":"room","id":"Room_Archaeology_Display","slug":null,
 "visibility":"public","weight":1.0,
 "name":{"text":"Archaeology Display",
         "termKey":"Rooms/Rooms/Room_Archaeology_Display_Name",
         "basis":"localized"},
 "aliases":[{"text":"archaeology","class":"id-token"}],
 "descriptions":[{"text":"…","termKey":"…"}],
 "icon":{"subObjectName":"UI_InGame_T_Icon_Room_Archaeology_Display",
         "guid":"…"},
 "buildId":20226581}
```

- **Membership rule (locale purity, localization-architecture §1):** a
  document exists in locale L iff the entity has ≥1 NON-EMPTY text
  RESOLVED IN L — a localized term edge with text in L's table, or an
  `mTerm` key resolving in L, or (any locale) a plain literal.
  Literal-bearing and dev-only entities therefore ship in the **en
  shard only** (the pivot); no locale shard ever contains another
  locale's fill (pivot-fill banned, piece-07 L4 posture). The manifest
  reports `devOnlyDocs` per kind (G4 population: 779 item + 718 config
  + 46 metagame-node name-fields) so the site can implement its own
  declared fallback by merging the en shard as a SECONDARY corpus —
  an explicit site-lane choice, never baked into the shards.
- **Name resolution priority (pinned):** localized name-class edge
  (first in sorted `(fieldPath,dstId)` order) → `mTerm` resolution →
  plain literal → convention/curated (courses, §S3). `basis` enum:
  `localized | mterm | literal | dev-fallback | convention | curated`.
  student-type: `LocalisedNameF` is the name, `LocalisedNameM` rides
  as a `name-variant` alias; staff `Ranks[].TitleM/F` (30 instances)
  ride as `name-variant` aliases.
- **Cleaning (before any text lands):** strip `<[^>]+>` tags and
  `\{[^{}]+\}` placeholders; texts cleaning to empty are DROPPED and
  counted (expect 23 name titles, F9) — never indexed as `""`.
  Descriptions are drawn ONLY from RESOLVED localized edges whose
  fieldPath contains `Description` (config `Description`/
  `FlavourDescriptions[]`, item `Description`, room
  `Description`/`LongDescription`); `_dev` placeholder prose (course
  ×41 "Brief description of the item…") is NEVER a description — dev
  text surfaces only as a name fallback or `dev-string` alias.
- **Field slots:** `slug` stays `null` today (F1: 100 % null) — the
  slot exists so a site-layer slug regime can land without schema
  churn. `icon` carries `IconReference.m_SubObjectName` (+GUID when
  present) as a REFERENCE only — icon bytes/CDN paths are the media
  piece's contract; sprite names are NOT aliases (noise, scout §2
  "optional"; census recorded in the manifest as
  `excluded.spriteNameCarriers` with the flip path named).
- **Visibility (G8 scope decision, Documentator-owned per scout §8):**
  enum `public | internal`. The measured campus-level dev roster ships
  `visibility:"internal"` — verbatim: `Blank Level`, `Free Play
  Level`, `IL3 Video 1`…`IL3 Video 5`, `IL3 Demo Level`,
  `Mark's Test Scenario`, `September 2020 Milestone`,
  `Test Level` (11 rows). Public: `All buildings`, `Knight Level`.
  The 4 null-name campus-levels emit no document at all. Flipping the
  roster is editing one pinned list, not code.
- **Sort/order:** shards sorted by `(kind,id)`; all arrays sorted
  (aliases by `(class,text)`); UTF-8 LF JSONL, compact separators,
  sorted JSON keys — byte-stable reruns.
- **Titles projections** `titles/<locale>.jsonl`: the slim slice
  `{kind, id, t}` (`t` = cleaned name text, verbatim from the shard's
  `name.text`) — the shell's instant-box hydration plane. Derived
  strictly from the same run's shard (asserted row-for-row).

   - **BuildId changed:** `DRIFT:` summary old→new per headline

     a regression verdict across builds (piece-07 L6 precedent).
   - **Improved member** (fewer missing/dangling/misses, more edges):
     informational `DRIFT:`, fresh value becomes the new seed.
   Rationale: tolerance never masks — at a fixed buildId, deterministic
   reruns reproduce identical upstream counts, so ANY bound breach is
