## 1. Goal

The landed corpus holds complete *rows* (13,443 stub entities across 9
kinds) but almost no *relations*: the only file under `extracted/relinks/`
is stage-5's `locale_availability.jsonl`, which measures 0 rows because
stage-5's seeded join procedure (payload-string == matrix-key) is
mechanically wrong for this game (scout §2 REFUTED it; the real
mechanism is a signed int32 term ID through an I2 registry).

This piece turns the corpus into the doctrine's relink layer:

- ONE new entrypoint stage — `relink` — that derives, deterministically
  and from committed artifacts, the complete ordered-pair relation
  matrix over the entity kinds plus every extended relation family the
  client data carries (locale terms, asset-GUID targets, scenes);
- the full pair datasets behind every modeled cell;
- the UI-link coverage map (bar 2) and the competitor-model application
  (bar 3);
- a regenerated `RELATIONS.md` catalog replacing its placeholder.

Everything runs through the single entrypoint ([DR-2026-08-18-pipeline]):
`python run_all.py <game-dir> --only relink` must reproduce every
declared output byte-identically. Site/UI anything, media export, and
PROOF derivation stay out (§6).

### R1 — Bridges (identity passes over the bundles)

Two deterministic UnityPy light passes over all 176 roster bundles
(same fallback-version seeding as stage 3 — headers read `0.0.0`,
seed from `identity.json.unityVersion`, count usage). These produce the
two indexes every resolver downstream needs; nothing else on disk
carries them (F11).

1. **CAB index** — per bundle, the names of its inner serialized files
   (`CAB-<hex>`) and, per serialized file, its object pathIds + classes.
   Emitted as `extracted/relinks/bridges/cab_index.jsonl`, one row per
   serialized file:
   `{bundle, cab, objects:[{pathId, class}], buildId}`, sorted by
   `(bundle, cab)`.
2. **Container/address index** — per bundle, UnityPy's container map
   (address → object). Emitted as
   `extracted/relinks/bridges/container_index.jsonl`, one row per
   address: `{bundle, address, pathId, class, buildId}`, sorted by
   `(bundle, address)`.

### R2 — Ordered-pair matrix + pair datasets (bar 1)

**Node universe (pinned):** the 9 stub kinds PLUS `scene` = **10
nodes**. Arithmetic the whole contract hangs on: 10 nodes → **100
ordered cells = 90 off-diagonal pairs + 10 diagonal self-pairs**. The
`scene` node's id space = the `bundle-roster.jsonl` rows with
`sceneFlag != none` (26 scene-carrying bundles on this install), ids
verbatim `relpath` values — scene objects have no stubs by design; the
maps piece consumes this seam. **Scene-edge attribution rule (the
emission path that keeps the node live):** when any resolved target
lands in a roster bundle whose `sceneFlag != none` and that target is
not itself a stub entity, the edge attributes to the scene node —
`dstKind:"scene"`, `dstId` = that roster row's `relpath`. Attribution
chain: the resolving bridge already names the owning bundle
(`container_index` for GUID targets; `externals → cab_index` for
cross-file PPtrs) → roster `relpath` lookup. So every destination-side
scene cell (`<srcKind>→scene`, 9 cells) emits from the same walkers
below; the source-side cells (`scene→<dstKind>` plus the diagonal,
10 cells) have no stub-payload emitter by design and each ships
`missing`/`partial` with an explicit `unblock` naming the maps piece's
scene-dump walk as owner — never silent, never structurally dead.
(Rationale for the 10th node: scout §1
names `campus-level → scene` as a live needs-probe and spec.md's
relation seeds need course↔campus-level↔scene adjacency; routing it
through the matrix keeps the completeness claim mechanical instead of
prose.)

**`extracted/relinks/matrix.json`** — one row per ordered cell, ALL 100
cells shipped, none droppable. `pairs[]` ordering is PINNED: row-major
over `meta.nodeUniverse.nodes` (the AC5 byte-determinism gate hashes
this array, so its order is contract, not convention):

```json
{"meta": {"buildId": 20226581,
          "nodeUniverse": {"nodes": ["config","item","room","course","staff",
                                     "student-type","unlockable","metagame-node",
                                     "campus-level","scene"],
                           "arithmetic": "10 nodes -> 100 ordered cells "
                                         "= 90 off-diagonal + 10 diagonal"},
          "enums": {"mechanism": ["hard","logic","inferred"],
                    "status": ["modeled","partial","missing"]}},
 "pairs": [{"srcKind":"room","dstKind":"item",
            "joinKey":"PPtr(m_FileID,m_PathID)",
            "mechanism":"hard","status":"modeled",
            "cardinality":{"perSrc":"0..N","perDst":"0..M",
                           "srcEntitiesWithEdges":59,"edges":110},
            "pairFiles":["room_item.jsonl"],
            "evidence":{"topFields":{"RequiredItems[].DefaultItem":110,
                                     "RequiredWorkingItems[]":22}}},
           {"srcKind":"course","dstKind":"room",
            "joinKey":"none-established","mechanism":"inferred",
            "status":"partial",
            "cardinality":{"perSrc":"0","perDst":"0",
                           "srcEntitiesWithEdges":0,"edges":0},
            "pairFiles":[],
            "unblock":"direct edge not found; chain runs course->config "
                      "(SelfStudyAssignments[].Definition) then config->room; "
                      "re-check after cross-file PPtr resolution lands"}]}
```

Frozen vocabularies: `joinKey` ∈
`PPtr(m_FileID,m_PathID)` ·
`AssetGUID(m_AssetGUID)->catalog.guid->container-address->pathId` ·
`LocalisedString(_termID)->I2-termID->Term-key` ·
`name-equality(<rule>)` · `none-established`.
`mechanism` ∈ `hard|logic|inferred`; `status` ∈ `modeled|partial|missing`
(doctrine words). Rules:

- `modeled` = carrier mechanism established end-to-end and edges
  emitted to a named `pairFiles[]` entry.
- `partial` = carrier identified but residue named (cross-file targets
  unresolved, bridge misses, needs-probe populations) — `unblock` key
  REQUIRED stating the concrete next probe.
- `missing` = no carrier found in client data today — `unblock` key
  REQUIRED. Missing-with-unblock is a legitimate terminal state
  (doctrine bar 1); silence is not.
- Diagonal cells ship too (`config→config` GOOSE graph lattice is the
  largest relation family in the game — 2,528 source entities).
- Counts are RE-MEASURED every run from the emitted datasets — the
  scout's F12 numbers are seeds to reconcile against, never constants.
- Ref-vs-row semantics (defined once): `cardinality.edges` counts
  DEDUPED emitted rows for the cell; `evidence.topFields[*]` counts RAW
  references before repeat-collapse. The `room→item` example above is
  the worked case: `edges:110` deduped rows beside
  `110 + 22 = 132` raw refs across two fields.

**Pair datasets** — `extracted/relinks/<srcKind>_<dstKind>.jsonl`, one
file per cell with ≥1 emitted edge, kind values verbatim (hyphens kept:
`campus-level_config.jsonl`, `student-type_config.jsonl`). Seeded mode
set = F12's 20 measured pairs (18 same-file PPtr + 2 GUID-carried
campus-level cells) + the two orchestrator-named
probe cells `unlockable_campus-level` (no measured carrier today — scan
unlockable payloads for `Levels[]` / `LevelFilters` / level-name
segments) and `metagame-node_course` (needs-probe:
`.references.NNNN.data.Course` PPtrs whose targets were not stub
entities — resolve via R1 bridges against scene/prefab-resident
objects, ledger what still dangles). Every other cell starts
`missing`/`partial` and earns rows only through a measured carrier.

Row shape (frozen; NO additional or missing keys):

```json
{"srcKind":"room","srcId":"Room_Archaeology_Display",
 "dstKind":"item","dstId":"Item_Door_Building_Archaeology_Display",
 "mechanism":"hard","method":"pptr-same-file","inferred":false,
 "evidence":{"fieldPath":"RequiredItems[].DefaultItem",
             "srcBundle":"rooms_assets_all.bundle","srcPathId":-851,
             "dstBundle":"items-general_assets_all.bundle","dstPathId":4021,
             "refCount":1},
 "buildId":20226581}
```

- `method` frozen vocabulary: `pptr-same-file` · `pptr-cross-file` ·
  `assetguid-catalog` · `i2-termid-registry` · `name-convention:<rule>`
  · `code-analysis:<descriptor>` · `competitor-model:<source-id>`.
- `inferred:false` ONLY for verbatim reads (`pptr-*`, `assetguid-*`,
  `i2-termid-*`); everything convention-, code-, or community-derived
  is `inferred:true` with `method` naming the rule (doctrine Principle
  one; piece-1 provenance flags semantics).
- `evidence` keys validated per method: PPtr edges carry
  `fieldPath, srcBundle, srcPathId, dstBundle, dstPathId, refCount`;
  cross-file adds `extFileId, dstCab` +
  `resolvedVia:"externals+cab-index"` — `dstCab` names the resolved
  serialized file because Unity pathIds are per-serialized-file and
  bundles carry several (222 files across 176 bundles, F3), so
  `(dstBundle, dstPathId)` alone under-determines a target; the same
  identity is what `_unresolved_pptrs` already models as `extPath`;
  GUID edges carry `fieldPath, assetGuid, catalogAddress`. Dedup
  identity is unchanged by this (evidence is not part of the tuple).
  `refCount` collapses repeats inside one array field into one row.
- Dedup identity: `(srcKind, srcId, dstKind, dstId, method, fieldPath)`.
- Sort: lexicographic by that same tuple. Ids ALWAYS verbatim — never
  slugified, case-folded, or trimmed (Principle one; the byte-match
  test enforces it).
- Cross-file resolution procedure (now UNBLOCKED by F3/F11): walk stub
  payloads for `{m_FileID, m_PathID}` leaves; skip `m_FileID == 0`
  zero-targets, `m_GameObject` leaves, and `m_Script` leaves (script
  identity already ships in-band on stub rows as `_scriptClass` — do
  NOT duplicate it as a relation family); resolve `m_FileID > 0`
  through `externals.jsonl` (bundle → fileId → CAB/built-in path) →
  `cab_index.jsonl` (CAB → candidate bundles) → `(bundle, pathId)` →
  stub index → emitted stub id (twins keep their `@hash8` suffix —
  F10). A resolved `(bundle, pathId)` ABSENT from the stub index whose
  bundle carries `sceneFlag != none` in the roster emits the edge as
  `dstKind:"scene"` / `dstId` = roster `relpath` (attribution rule,
  node universe above) instead of falling to `_unresolved_pptrs`.
  Built-in externals (`Library/unity default resources` et al.)
  are not entity targets: count them, ledger them, never resolve them
  into pairs. Unresolved cross-file refs stay visible: per-cell
  `unresolvedRefs` counter in matrix evidence + a
  `relinks/_unresolved_pptrs.jsonl` ledger
  `{srcKind, srcId, fieldPath, extFileId, extPath, m_PathID, reason, buildId}`
  — sorted by `(srcKind, srcId, fieldPath, extPath, m_PathID)` (pinned;
  the global "sorted enumeration" discipline names no key for this
  file) — gapped resolution is data, never silence.
- Axes provenance (scout §3): each row inherits `sourceAxes` from its
  endpoint rows' `axes` when present (omitted when both absent — most
  rows); twin endpoints keep the `@hash8` id as `dstId`/`srcId` and the
  verbatim original stays reachable through the stub row's
  `fields.id`. No axis-scoped collapsing anywhere.
- Content-axis vocabulary stays the piece-1 enum
  `base | dlc-space | dlc-ghost` wherever an axis value is emitted.

### R3 — GUID bridge

Procedure (each step's failure mode ledgered, never swallowed):

1. **catalog-GUID→address index**: filter `catalog.json` keys with
   `kind == "guid"` → `guid → [{bundle, address}]` (54,143 distinct on
   F5; duplicate-guid keys are legal Addressables and ship as a list).
2. **address→object**: `container_index.jsonl` resolves
   `(bundle, address)` → `pathId` (+ class).
3. **object→entity**: exact-match rules against the stub index — (a)
   dump identity `(bundle, pathId)` present in export-manifest → stub
   row; (b) otherwise, if the resolved object's bundle carries
   `sceneFlag != none` in the roster, the edge attributes to the scene
   node (`dstId` = roster `relpath`; the R2 attribution rule — this is
   how `campus-level→scene` and kin reach emission); (c) otherwise the
   target is a NON-entity object (sprite atlas,
   texture, prefab component): the edge terminates at the ADDRESS, not
   an entity.
4. **Emission**: GUID references FROM stub fields (`m_AssetGUID` /
   `IconReference` shapes) emit rows into
   `extracted/relinks/entity_asset_guid.jsonl` —
   `{srcKind, srcId, dstKind:"asset", dstId:<catalog address verbatim>,
     mechanism:"hard", method:"assetguid-catalog", inferred:false,
     evidence:{fieldPath, assetGuid, subObjectName?, resolvedVia}, buildId}`
   sorted by `(srcKind, srcId, fieldPath, dstId)` — PLUS, where step 3a
   hits a stub entity, a second row into the corresponding kind-pair
   file (`campus-level_config`, `campus-level_metagame-node`) with
   `method:"assetguid-catalog"`, `dstId` = the resolved stub id, and
   where step 3b attributes the target to the scene node, a second row
   into the corresponding `<src>_scene` pair file with `dstKind:"scene"`,
   `dstId` = roster `relpath`. This
   is how the two campus-level cells (F12) reach `modeled`.
5. **Resolve-rate is an EMITTED FACT**, never prose:
   `extracted/relinks/guid_bridge_report.json` =
   `{guidRefsTotal, distinctGuids, resolvedToAddress, resolvedToStub,
     danglingDistinctGuids, resolveRateAddress, resolveRateStub, buildId}`.
   Scout-time expectations to reconcile: 20,042 refs / 5,548 distinct /
   79.7% address-resolve / 1,137 dangling (F9).
6. **Dangling ledger** (G3):
   `extracted/relinks/_dangling_guids.jsonl` — sorted by `assetGuid`
   (pinned, same rationale as `_unresolved_pptrs`) — one row per dangling
   GUID: `{assetGuid, sampleRefs:[{srcKind, srcId, fieldPath}] (≤5),
     verdict:"unresolved-open"|"resolved-scene"|"resolved-editor-only"|
     "removed-content", unblock?, buildId}`. Verdicts upgrade via a
   bounded probe against scene dumps + census (one pass, deterministic);
   anything still `unresolved-open` keeps exit 2 honest (§5.7).

### R4 — Locale join v2 (the term-ID path) — ownership PINNED

Mechanism (scout §2, measured end-to-end): entity field
`{_dev, _termID}` → int32 term ID → I2 registry ID → `Term` key →
locale-matrix key. The GUID/localization hypothesis of the R10 era is

`relinks/locale_availability.jsonl`; this piece NEVER writes that
file.** This piece owns NEW files instead. Why: (a) single-writer
invariant — piece-1 Revision 2/R3 cut a two-writer regression hazard on
exactly this path; reopening it trades a known hazard for cosmetics;
(b) forward-only stage DAG — the registry below is PRODUCED AFTER
stage 5 runs, so making stage 5 consume it would make stage-5 output
depend on whether a LATER stage had ever run (breaks first-run
convergence + idempotence gates); (c) the v1 file is honest as it
stands — 0 data rows, with the refuted procedure's zero-yield
documented in stage-5's `joinEvidence` block in the EXTRACTION-LOG run
sections (the file itself carries no such block).
Consumers are routed: RELATIONS.md names
`entity_locale.jsonl` as the authoritative entity-granular locale
relation. (Retiring the v1 artifact outright needs a piece-1 revision —
routed in §7, not done here.)
