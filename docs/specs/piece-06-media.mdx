## 1. Goal

Piece 1 deliberately stopped at catalogue rows: zero decoded image
bytes have ever landed under `extracted/`
([DR-2026-08-18-media-scope]; the owner pick this piece executes is the
one that ruling scheduled). The corpus meanwhile proves the entity→icon
join is already ~solved by landed artifacts — **2,151 of 2,158 distinct
referenced icon sprites resolve (99.676%)** through
catalog-GUID → container-index → media-catalogue, the crop geometry is
fully measurable (`m_RD.textureRect` present on 6,787/6,789 sprites),
every texture format in the client decodes through UnityPy + Pillow
(zero ASTC/ETC2), and the deliverable is megabytes, not gigabytes
(**108,445,749 px source crop area ≈ 8–25 MiB shipped WebP q80**).

This piece adds ONE entrypoint stage — `media` — that deterministically
exports the web-ready icon/art layer:

- **E1**: the entity-referenced icon set (the 2,158-ref set; 2,151
  resolved, 7-name absence ledger);
- **E2**: the standalone-Sprite route (~150 empty-sub refs the atlas
  path cannot express);
- **E3**: UI-chrome atlas crops for all 3,154 packed slots
  (flag-gated, scope-ladder second step);
- **E4**: the render-data pairing rule (≈46% NULL texture pointers)
  plus the pixel-exact AssetStudioModCLI cross-check lane;
- **E5** (optional, report-only): the course-icon carrier probe.

Everything runs through the single entrypoint ([DR-2026-08-18-pipeline]):
`python run_all.py <game-dir> --only media` reproduces every declared
output byte-identically. Site/CDN work, generative art, audio/video/
mesh/font export, and PROOF derivation stay out (§6).

### S0 — Scratch discipline (hard preflight, runs FIRST)

ALL decode scratch — page decode buffers (worst page 4096²×RGBA =
64 MiB), intermeds, AssetStudioModCLI export dirs, temp encodes — goes
to a temp root on **D: or A:. NEVER C:.**

- Temp root resolution: `--temp-root` arg > `TPC_MEDIA_TMP` env >
  `TPC_TEMP_ROOT` env > `<extracted-root>/.tmp-stage11`. After
  resolution the stage resolves the drive letter of the temp root and
  of the output root.
- **Hard gate:** resolved temp root on drive `C:` ⇒ **exit 3** printing
  the resolved path + remediation (`set TPC_MEDIA_TMP=D:\...`). No
  override flag exists — a C:-temp run is not runnable, by contract.
- Free-space floors, measured and printed: temp root ≥ **4 GiB** free,
  output root ≥ **2 GiB** free; below floor ⇒ exit 3 with measured
  numbers (M18: C: sat at 0.07–0.36 GiB mid-session; the floors exist
  so a sibling-pressure crash is a clean refusal, not a half-written
  tree).
- Every scratch path the stage creates is logged in the run section
  (`tempRoot`, `tempRootDrive`, `outputRootDrive`, free-GiB readings)
  and REMOVED on completion (scratch is never a declared output).

### E1 — Entity icon set (primary deliverable)

Universe: every sprite-typed GUID reference in the nine stub kinds —
recursive walk over `stubs/<kind>.jsonl` `fields.*`, filter
`m_SubObjectType startswith UnityEngine.Sprite`, keyed on
`(kind, srcId, fieldPath)` with `m_AssetGUID` + `m_SubObjectName`.
This is the SAME walk the verification rounds ran; it is authoritative.
`entity_asset_guid.jsonl` is consumed only as a reconciliation surface:
sprite-shaped refs found by the E1 walk vs rows persisted by stage-6
are counted both ways; a delta ⇒ `DRIFT:` line + both counts in the run
section (never a failure — that file is another stage's artifact).

Join ladder per ref (all steps landed artifacts; nothing re-derived):

```
stub.fields.*Reference.m_AssetGUID
  → catalog.json guid-kind key → address(es)      (54,143 distinct guids)
  → container_index address → (bundle, class, pathId)
  → media-catalogue Sprite row by subObjectName    (name index)
```

Rules pinned:

1. **Resolution is BY NAME across bundles** (M10): the sprite object is
   located via `container_index` wherever it actually lives — never
   bundle-local lookup against the atlas-def's bundle (wrong for 2,059
   refs / 820 names).
2. **Route classification per ref** (drives emission mechanics):
   `atlas-pair` (targets `.spriteatlasv2`, non-empty sub → crop from
   the atlas page via E4 pairing) · `standalone` (targets plain
   `Sprite` → E2) · `unresolved` (→ `_missing_icons.jsonl`).
3. **One file per distinct sprite**; many entities may reference it —
   `index.jsonl` carries the many-to-one mapping, the manifest carries
   the file. Dedup identity: the emitted filename (§4 naming).
4. **Crop geometry**: the sprite's own `m_RD.textureRect`
   `(x, y, w, h)` in the PAGE's texture space; Unity rects are
   BOTTOM-origin, so the crop step converts to image space
   (`top = pageHeight − y − h`) BEFORE cutting — the conversion is
   proved right by the E4 pixel-exact lane, not asserted.
5. **Rounding rule (pinned, determinism-critical):** 3,460 sprites
   carry fractional rects. Round EACH of x/y/w/h with
   round-half-away-from-zero (NOT Python's banker's `round()` —
   `floor(v + 0.5)` or `decimal.ROUND_HALF_UP`), THEN derive
   `top`/bounds from the rounded components. Bounds-checked after
   rounding (see EC).
6. **Absences:** the 7 unresolved names land in
   `_missing_icons.jsonl` with `reason: dlc-content-absent` (6) /
   `stale-name` (Cheeseball) + ≤5 sampleRefs each — exit-2 ledger
   material, never silence, never a hard failure.
7. `EditorFallbackIconReference` (351, editor-only; GUIDs absent from
   runtime catalog AND containers) and the non-icon danglings
   (`VisualsPrefab` 12, `Meshes[0]` 26, `LevelConfig` 7) are
   LEDGERED-SKIP rows in `_missing_icons.jsonl` with their own
   `reason` values — counted, never dropped silently.

### E2 — Standalone-Sprite route

~153 refs target plain `Sprite` assets (`AdvisorMessage.CharacterImage`,
loadingscreen/character images in `ui-art*`/`ui-loadingscreens*`
bundles), 150 with EMPTY `m_SubObjectName`.

- Locate the Sprite object via `container_index` on the ref's resolved
  address; decode the sprite directly (UnityPy `Sprite.image` path or
  E4 pairing when its texture pointer is NULL — the same rule applies).
- **Pass-through rule:** a sprite whose rect covers its entire texture
  (492 corpus-wide; measure per sprite) is emitted as a straight
  texture re-encode, no crop.
- **Naming for empty-sub sprites:** the address basename from
  `container_index` (fallback ladder: container address basename →
  `{bundle-stem}_{signed pathId}`), because `subObjectName` does not
  exist to key on. Rows carry `namedBy: address-basename` in the
  manifest so the later slug/rename pass can find them.
- Empty-string sub values (wide-universe finding, M20) are ledgered as
  `reason: empty-sub-name` refs in `_missing_icons.jsonl` when they do
  not resolve to a locatable object; they never fabricate a filename.

`--include-ui-chrome` (default OFF; the default run ships E1+E2+E4

non-goal); a future targeted pull is a per-asset flag, not a family
sweep. Expected added volume ≈ tens of MiB (scout §8 stretch row).

### E4 — Render-data pairing + cross-check lane

The mechanism sub-pass every route depends on:

1. **Pairing rule (M9):** for sprites with NULL `m_RD.texture`
   (3,140 ≈ 46%), resolve the home page through the OWNING ATLAS's
   `m_RenderDataMap`, matching entries to the sprite's OWN
   `m_RD.textureRect` SIZE. Never assume index alignment
   (`m_PackedSpriteNamesToIndex` — provably wrong, 0/352). Match
   failures on a referenced sprite ⇒ exit 1 naming the sprite (a
   referenced sprite with no locatable page means the grammar model is
   broken, not that art is missing).
2. **Decode breadth:** pages are decoded ONCE per run, cached in the
   temp root as raw RGBA arrays, and cropped N times (pages host dozens
   of slots). Decode path must not assume BC1/BC3 — the single BC7
   page (M11) must decode through the same code path.
3. **Cross-check lane (acceptance surface):** export a deterministic
   sample of **≥20 referenced sprites** through AssetStudioModCLI
   (`--unity-version 2020.3.47f1`, exports into the temp root — never
   the repo), then compare OUR decoded crop vs the CLI export:
   identical dimensions AND 0 differing pixels (maxDelta 0) required.
   Sample composition pinned: ≥1 per route (`atlas-pair`,
   `standalone-pass-through`, `direct-pointer-subrect`), ≥2
   fractional-rect sprites, the BC7-page sprite if referenced, both
   probe anchors `DLC2_Qualifications_janitor_SML` + `_LRG`, remainder
   filled by deterministic stride over the sorted name list. Result
   emitted to `crosscheck-report.json`; `pixelMatchRate < 1.0` ⇒
   exit 1. Comparison runs on PIL/numpy stats — **never Read a binary
   image into agent context** (house rule; validate numerically).

### E5 — Course-icon carrier probe (OPTIONAL, report-only — recommended shape)

Recommendation, ruled here so the builder doesn't improvise: E5 exists
as a **default-OFF, report-only probe** (`--probe-course-carrier`),
scoped to answer scout §9 Q1 from landed artifacts — it NEVER emits an
icon and NEVER writes outside `extracted/media/`. Why report-only
rather than a full sub-pass: the carrier is a RELINK-layer question
(the chain runs course → Qualification → config → Courses-Qualifications
sprites; `relinks/course_config.jsonl` already holds 652 edges), while
this piece's emission set is hard-join only — wiring in the 9/69
name-convention guess would put `inferred:true` art into a
`inferred:false` plane. The probe emits
`course-icon-carrier-report.json`: the qualification-chain walk results,
the 42-sprite inventory, the strict-convention yield (seed 9/69), and
the 28/69 PPtr population — everything the later relink revision needs,
costing one bounded pass. Making it an explicit non-goal instead was
rejected because AGENTS rule 8 puts this question in the data layer and
the probe is cheap; making it a full emission pass was rejected for the
plane-mixing reason above.
