## 1. Goal

The corpus is measured and reconciled — but none of that is
machine-checkable. Today nobody compares artifact A to artifact B unless
an agent re-derives the comparison by hand each session; the scout's
closing analysis names this disease twice (G2/G4/G5 are
"nobody-compares" gaps; G1/G3 are "the number is right and its unit is
undocumented" gaps). None of the three probed competitors publishes
versioned schemas or validators — their contracts are implicit in
payloads. This piece beats that precedent: explicit, tracked,
machine-checkable pins.

Deliverables:

- a **tracked contract layer** — `contracts/` at pack root (decision +
  justification §3.1) holding per-family human-readable contracts that
  are generated-and-checked against artifacts by validators under
  `tools/`; the markdown layer is versionable, the JSONL data stays
  local;
- a **pin taxonomy** applied per family (§4) — schema-pin, invariant-pin,
  cross-family-pin — with the measured values pinned as constants or,
  preferentially, as derived identities (§3.5);
- **exception pins** consumers must be told about (§5), **counter-unit
  pins** (§6), and **ledger-gap pins** (§7);
- a **red→green harness**: validators that FAIL today on exactly the
  three real breaks that survive the correction round (§9), going green
  after named emitter amendments — everything else lands GREEN;
- mechanical acceptance incl. deliberate-mutation teeth proof (§11).

This is a data-completeness piece under AGENTS rule 8: the Phase D site
consumes contracts, never derives data. Its primary reader after the
build pair is the site builder (exception sheet §5), the PROOF piece
(#11 consumes §7's ledger inventory), and every future fixer (the pin
suite tells them within seconds whether a change broke a cross-artifact
identity).

## 3. The contracts stage family

### 3.1 Tracked-layer decision: `contracts/` tree, not `extracted/CONTRACTS.md`

**Chosen: a `contracts/` tree at the TwoPoint pack root.** Justification:

1. **The README already reserved it.** Pack README layout table:
   `contracts/` — "emitted dataset contracts — later pieces". This piece
   IS that later piece; honoring the reservation avoids re-plumbing the
   documented layout.
2. **Tracked by default policy, not by an ignore exception.** The pack
   `.gitignore` ignores `extracted/**` with the carve-out
   `!extracted/**/*.md`. A contract layer inside `extracted/` would
   depend on that exception surviving every future gitignore tightening;
   the whole point of the scout's finding #1 is that contracts MUST live
   in robustly tracked paths. `contracts/` at pack root sits beside
   `docs/` and `tools/` — tracked unconditionally.
3. **Pins need a machine-readable sibling.** Validators must consume
   pins as data (§3.2); a single markdown file cannot host per-family
   machine slices cleanly. The tree gives each family a doc + a slice of
   one JSON manifest.
4. **Ownership clarity.** Everything under `extracted/` is
   pipeline-emitted and local (md carve-out aside). Contracts are
   repo-first products DESCRIBING those outputs; mixing a maintained
   contract doc into the emission tree blurs who writes what.
5. Rejected alternative recorded for the reviewer:
   `extracted/CONTRACTS.md` (scout §8 recommendation) remains viable and
   tracked today, but fails criteria 2–3; if the reviewer prefers it,
   the only changes are path constants in §10 — nothing else in this
   spec moves.

### 3.2 Layer model

```
contracts/pins.json          MACHINE source of truth — every pinned constant,
                             enum, uniqueness claim, reconciliation, unit
                             definition, ownership rule, build scope.
                             Sorted keys, UTF-8, LF. Committed.
contracts/families/*.mdx     HUMAN per-family contracts (prose judgments +
                             a fenced ```pins block that MUST canonically
                             equal the family's pins.json slice).
                             Generated-and-checked: the runner re-renders
                             the blocks; stale prose numbers fail (V-D3).
contracts/red-registry.json  Deliberately-red validators awaiting their
                             fixing amendment (§9). Committed input.
tools/stage10_check_contracts.py
                             Runner + validator implementations
                             (explicit-10 naming per the orchestrator
                             stage-index registry, F1). Read-only over
                             extracted/.
tests/test_contracts_*.py    Hostless fixture lane + mutation harness.
```

Data flow: validators read `pins.json` + local artifacts under
`extracted/` → emit the §3.4 report → exit. The MDX layer never feeds
execution; it is kept honest BY execution (V-D3). The JSONL datasets
stay local-only forever; git history of `contracts/` IS the contract
change history.

### 3.4 Exit codes and output grammar

Exit codes reuse the house vocabulary:

- `0` — all registered validators PASS (steady state once §9's reds
  close and the registry empties);
- `2` — completed-with-known-ledger: every failing validator is listed
  in `contracts/red-registry.json` with its fixing amendment (EXPECTED-
  RED lines; loud, non-silent, pipeline continues);
- `1` — contract broken: any UNEXPECTED FAIL, PIN-STALE, or unit-typed
  reconciliation refusal;
- `3` — inputs missing (cannot check).

Output grammar (one line per event, sorted by validator id, then a final
summary line; no timestamps):

```
PASS [V-S3] stubs/config.jsonl 8430/8430 rows conform
FAIL [V-R1] relinks/matrix.json expected=24583 measured=24581 hint=Σ cardinality.edges
EXPECTED-RED [V-L1] red-registry entry=uncontained-address-ledger fix=piece-05-amendments
PIN-STALE [V-D4] pin=buildScope.buildId pinnedBuild=20226581 currentBuild=<new>
PIN-MISMATCH [V-S2] pin=families.stage0.roster.dirClass expected="158/10/8" measured="157/10/8"
INFO [V-S11] enum arm 'logic' declared, 0 occurrences
{"passed":N,"failed":N,"expectedRed":N,"stale":N,"info":N,"exit":"0|1|2"}
```

Every FAIL names: validator id, artifact, PINNED expectation, MEASURED
value, one-line hint. That quadruple is the failure-output shape for all
validators in §8; per-validator cells below define only the
expected/measured payloads. Two non-FAIL loud spellings share the same
grammar (F8): `PIN-STALE` = the pin's build scope differs from the
corpus build (§3.5); `PIN-MISMATCH` = the measured value differs from
the pinned constant AT the pinned build. Both exit 1.

### 3.5 Derived-over-transcribed; buildScope and PIN-STALE

Two rules keep the pin set from rotting:

1. **Derived beats transcribed.** Whenever a constant can be RECOMPUTED
   from sibling artifacts (matrix edges Σ == pair rows; reverse usages ==
   entity_locale rows; bridge replay == report), the pin is the
   IDENTITY, not the number — it can never go stale. Transcribed
   constants are used only where derivation is impossible (per-kind row
   counts, enum populations, the catalog dupe identity) and each carries
   `"kind": "constant"`.
2. **Constants are build-scoped.** Every constant sits under
   `pins.buildScope = {buildId: 20226581}` semantics: when
   `identity.json.buildId` differs from the scope, constant-scoped
   validators emit `PIN-STALE` (exit 1, `--warn-stale` downgrades to
   INFO for exploratory runs) instead of pretending to pass. Re-pinning
   after a game patch is a deliberate reviewed commit of `pins.json` —
   measured numbers win, prose gets corrected, never silently.

This deliberately DIFFERS from stage-seed DRIFT discipline
(piece-02 §2): seeds describe nature and fresh wins automatically;
contract pins are the product promise and movement is a reviewable
event. Both disciplines coexist; validators print `PIN-MISMATCH` (not
`DRIFT:`) so the two never blur.

## 6. Counter-unit pins

The correction round's deepest lesson (G1 retracted, G3 downgraded): a
number can be RIGHT and still mislead everyone who reads it, when its
UNIT lives only in code. Pins:

1. **Units live IN the artifact.** Every emitted report whose fields
   carry counts (`guid_bridge_report.json`,
   `locale_join_report.json`, `base-overlay-report.json`,
   `catalog-coverage.json`) gains a `counterUnits` object mapping each
   numeric field to a unit string from the frozen vocabulary
   `reference-events | deduped-rows | distinct-keys | emission-events |
   walked-terms | skipped-cells | bytes | objects`. Emitted by EACH
   report's own generator (deterministic static dict + counts) — three
   emitters own the four reports: stage 2 (`catalog-coverage.json`),
   stage 4 (`base-overlay-report.json`), stage 6 (`guid_bridge_report.json`,
   `locale_join_report.json`). Validator V-U1 enforces presence +
   vocabulary membership.
2. **Run-section keys get inline unit comments.** Every EXTRACTION-LOG
   counter that names an emitted file states its unit beside the key
