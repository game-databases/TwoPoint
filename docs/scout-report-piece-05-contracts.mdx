## §1 Prior art + conventions this piece inherits

**House conventions already binding on any contract-pinning stage:**

1. **Determinism contract** ([piece-01 §4](./specs/piece-01-extraction-pipeline.mdx)):
   sorted enumeration + sorted JSON keys, UTF-8 + LF, temp-file +
   atomic-rename writes, no wall-clock inside stage outputs,
   byte-identical reruns (EXTRACTION-LOG, `.stage-stamps/`,
   `.pipeline-meta.json` excluded from comparison). Exit codes
   `0/1/2/3` with `2` = completed-with-ledger as relink's EXPECTED
   steady state.
2. **Verbatim identifiers** (doctrine Principle one): ids, GUIDs,
   path_ids, loc keys preserved byte-exact; curated views may ADD
   slugs, never replace originals. Enforced today by the stage-5
   byte-match test (checked=2,128, mismatches=0 at last run).
3. **Provenance two-class rule** ([DR-2026-08-15 D2]):
   `buildId` + coverage scope may reach user surfaces; everything else
   provenance-shaped stays repo-plane. Every emitted row carries
   `buildId` — measured 100% single-valued `20226581` on every family
   probed (stubs, roster, pairs, registry, locale rows, ledgers).
4. **Ledgered absence, never silence**: `_absences.jsonl`,
   `_unmapped-families.jsonl`, `_dangling_guids.jsonl`,
   `_unresolved_pptrs.jsonl`, competitor walls — gapped output is data.
5. **Seeds reconcile, fresh wins**: piece-02's `DRIFT:` discipline
   (measured numbers beat pinned constants; drift prints a line, never
   silently re-pinned). Two live DRIFT examples are in
   `EXTRACTION-LOG.md` (GUID bridge seed F9 20,042/5,548 vs measured
   20,170/5,584; campus-level→metagame-node seed fact 13 landing in
   `campus_level_config` because stage-5 kinded the carrier `config`).
6. **The git plane matters for contracts** (measured, `TwoPoint/.gitignore`):
   `extracted/**` is **local-only** except `extracted/**/*.md`. Game
   data never enters git — so the dataset FILES have no git history,
   and the contract layer (schemas, invariants, validators) MUST live
   in tracked paths (`docs/`, `tools/`, `extracted/**/*.md`) or it is
   unversioned. The pack README already reserves `contracts/` for
   "emitted dataset contracts — later pieces".

**External prior art** is in §7 (competitor precedent).

## §7 Competitor contract precedent

  `BreadcrumbList`, `CollectionPage` measured on an ARK database page).
  No public raw dumps; the contract lives in llms.txt + JSON-LD.
- **new-world.guide** — the de-facto API is Next.js
  `__NEXT_DATA__` embedded per page (measured on the sandworm
  firestaff item page): flat camelCase entity schema (`itemId`, `tier`,
  `rarity`, `gearScore`, `bindOnEquip`…) with **pre-joined relation
  arrays shipped in the same payload** (`possibleDrops`, `usedInRecipe`,

Net precedent: none of the three publishes versioned schemas or
validators — their contracts are implicit in payloads. That is the gap

machine-checkable pins + (later, site phase) an `/llms.txt` that states

## §8 Proposed pin taxonomy

Three pin classes, each with a VERIFY-vs-DOCUMENT ruling. Sizes make
verification cheap: every check below runs over < 200k rows / < 400 MB
(catalog.json being the one heavy artifact — validate at emit time
inside stage 2 where it is already parsed, or stream-check with jq).

**A. schema-pin** (VERIFY mechanically, per family — fail loud):

1. Exact top-level keysets per artifact family (§2 tables): stub row
   envelope (9 keys + optional `axes`), pair row (9 keys +
   optional `sourceAxes`), roster/export/externals/media/registry/
   coverage row shapes, locale `{id,text}`, matrix cell shape.
2. Filename grammars: kind↔filename map (already pinned piece-01 §3),
   signed-pathId stems `_(|-)\d+$` (Rev 6 lesson — a standing
   filename-grammar pin would have caught the unsigned-parser incident
   before the corpus existed), `<srcKind>_<dstKind>.jsonl` naming over
   the node universe, `contracts/` layout itself.
3. Frozen enums with measured domains (§4): reject out-of-vocabulary
   values; separately TRACK which declared values are unexercised so a
   new value is a reviewable event, not silence.
4. Sort orders: pair files lexicographic by dedup tuple;
   `_unresolved_pptrs` by its pinned 5-tuple; `_dangling_guids` by
   assetGuid; matrix `pairs[]` row-major; catalog keys sorted.
5. `buildId` present and equal to `identity.buildId` on 100% of rows
   of every family.

**B. invariant-pin** (VERIFY — these are the incident killers):

1. Uniqueness set from §3 (stub id per kind, relpath, outRelPath,
   container address, cab tuple, externals tuple, locale id per file,
   termId, dedup tuple) — PLUS the corrected claim for catalog.json:
   pin `key` as **non-unique** (documented exception) so consumers are
   told, and pin duplicate rows to be byte-identical.
2. Arithmetic reconciliations, all currently green and worth keeping
   green: matrix edges Σ == pair rows; cab objects == census Σ;
   media-catalogue rows == carved census per class; registry↔matrix
   diff == 0; reverse usages == entity_locale rows; catalog-coverage
   `keysTotal` == catalog rows; roster rows == enumerated bundles.
3. Counter↔artifact reconciliation for every EXTRACTION-LOG run-section
   counter that names an emitted file (`stubRowsByKind` == per-file
   counts, `edgesEmitted` == pair rows, …) — compared IN UNITS, never
   raw equality: the localisation `rows` case (§2 stage 4, §10 G1)
   proves a naive `counter == wc -l` pin would itself be the bug
   wherever emission-event units apply. Prerequisite pin: persist
   `duplicateKeysOverwritten`.
4. Structural rules: mapped-schema XOR documented-gap with
   gapReason+unblock on gaps; unblock REQUIRED on every partial/missing
   matrix cell; sampleRefs ≤5; sentinel `_termID==0` excluded from
   entity_locale while counted in the report; twin ids ⇔ `fields.id`
   presence; `sampled byteMatch checked > 0`.
5. Exit-code ledger contract: exit 2 iff any declared ledger is
   non-empty, with the run section naming every contributor + size
   (already specced piece-02 §5.7 — pin it as data, checked against the
   actual ledger files).

**C. cross-family-pin** (VERIFY by full scan — all universes are
small):

1. Id-resolution closure: pair srcId/dstId ⊆ stub ids (twins with
   suffix); `locale-term` ⊆ registry; `scene` ⊆ roster scene ids;
   `asset` ⊆ container_index addresses EXCEPT the pinned
   uninstalled-DLC carve-out (catalog entries with `bundle:null`, cf.
   the 19 out-of-roster references) — which must land in a LEDGER ROW
   instead of bare silent rows. Finds **G2**'s real gap (no ledger row
   for address-terminal uncontained edges) today.
2. Report derivability: every emitted report's counters must carry
   their UNIT DEFINITIONS inside the artifact and be replay-reproducible.
   `guid_bridge_report.json` already replays bit-exact (§3) but defines
   its reference-unit nowhere but source — the pin item is emitting the
   definitions, not fixing arithmetic (**G3**).
3. Bundle-name closure: every `*.bundle` reference in any artifact
   (stub `source.bundle`, export-manifest `sourceBundle`, pair
   evidence bundles, catalog `bundle`) resolves to a roster `relpath`
   by basename after the pinned normalization. Currently green — keep
   it green.
4. Ownership pins (DOCUMENT, enforce by grep): stage-5 sole ownership
   of `locale_availability.jsonl`; stage-6 sole ownership of the rest
   of `relinks/`; RELATIONS.md regenerated only by relink; the routed
   consumer note (v1 file honest-zero, authoritative relation is

5. Availability routing (DOCUMENT + one VERIFY): until G4 is fixed,

   `entity_locale.evidence.locales[]` are reserved-but-empty fields" so
   no site builder trusts the empty arrays.

Where pins live (recommendation, respecting the gitignore finding):
tracked validators under `tools/check_contracts.py` (or a
