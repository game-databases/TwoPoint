## Mandatory adjudications

### a. english-over-base reachability — REFUTED as "dead"; branch IS reachable; order NO implementation change

Traced the full ladder at `tools/stage4_localisation.py:175-182`
(`classify_composition`, arm at :180):

```
mixed             ← (base_only > 0 and en_only > 0) or differing > 0
base-over-english ← elif base_only > 0
english-over-base ← elif en_only > 0          ← REACHABLE
english-only      ← else
```

`english-over-base` fires iff `en_only > 0 ∧ base_only == 0 ∧
differing == 0`. Concrete reachable input: `base = {"a": "A"}`,
`english = {"a": "A", "c": "C"}` → shared={a} identical, differing=0,
base_only=0, en_only=1 → falls through arms 1–2 into :180. All four enum
values are reachable; CodeReviewer's refutation stands; TestWriter's
"dead english-over-base branch" finding is **REFUTED**.

**Which test assertion is wrong:** `tests/test_stage4.py:89` —
`policy({"a": "A"}, {"a": "A", "c": "C"}) == "english-only"`. That exact
input classifies as `english-over-base` under the impl ladder. The spec
(§3 stage 4 + §7) deliberately does NOT pre-pin label semantics
("selected by this stage's deterministic classifier … not pre-pinned"),
so a test may not fail the implementation over them. The likely origin
of the "dead branch" claim: the suite ran this input, got an unexpected
label, and inferred the branch was unreachable rather than that the pin
was unauthorized. Fix is test-side (T2 below); the implementation ladder
is correct and deterministic — **do not touch it**.

### b. stage-5 KeyError 'nameLoc' — CONFIRMED, BLOCKING (neither reviewer examined it)

Verified directly against `tools/stage5_emit_stubs.py`:

- :237-239 — `locales_per_field` comprehension filters
  `for f, key in joins.items() if key in matrix_keys`, i.e. HARD joins
  only (convention keys are never in `matrix_keys` by construction of
  the :222-232 if/elif);
- :242 — `named_fields = [f for f in joins if NAMED_FIELD_RE.search(f)]`
  ranges over ALL of `joins` (hard + convention);
- :243 — `named_pool = {f: locales_per_field[f] for f in named_fields}`
  → **KeyError** whenever any named field (`name|title|display`,
  regex :77) is convention-joined.

Trigger: any entity whose named-field join is convention-shaped — the
suite's `item_beta`/`nameLoc` fixture targets exactly this and is
correct and load-bearing. Not fixture-specific fragility: on the real
corpus any entity with only a convention-shaped loc field crashes stage
5 to exit 1, cascading ~8 suite failures (TestReviewer's cascade table).
Fix pinned as F2 below (fix `named_fields`' domain, not the lookup).

### c. D10 spec amendment — decision: adopt NOW, one line riding this fix round (SPEC lane S1)

always > 0. The implementation already reconciles the residual-inclusive
form (`tools/stage3_harvest_bundles.py:207-214`, incl. `residual` at

spec NOW rather than defer. Reasons: (1) the contract currently
contradicts the shipped, sane implementation — any literal re-check of
§3 against real outputs fails forever; (2) the coming fix round touches
exactly this acceptance (F11 extracts the helper the tests bind to), so
the spec must state what those tests assert; (3) the edit is one line,
zero behavioral change. Deferred amendments are how checklist-vs-
contract contradictions like O1 (§8 "script.json slice") happen — fixed
in the same pass here (S2).

### d. Fixture misplacement (globalgamemanagers at install root) — CONFIRMED real; assigned to TEST lane as non-blocking hygiene (T7)

poison a future manual smoke run.
