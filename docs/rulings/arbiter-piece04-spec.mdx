### R1 — Relink-vs-logic ownership of the prerequisite edges: logic-owned CONFIRMED — but the stated reason is REFUTED, and a reconciliation leg becomes mandatory

The documentator chose logic-owned "after measuring relinks carries
neither edges nor unresolved rows". I probed harder than that probe:

1. `extracted/relinks/config_config.jsonl` carries **68 rows whose
   `evidence.fieldPath` is `references.<hex>.data._course`** — 59 as
   `method:"pptr-cross-file"`, `mechanism:"hard"`, `inferred:false`,
   `resolvedVia:"externals+cab-index"` (dstCab `cab-7c07bcb2…`,
   extFileId 2), 9 as `pptr-same-file`; 68 distinct carrier ids, sample
   `CareerChallenge_Course_Archaeology_V1 → Course_Archaeology_Lite`.
   By typed class these decompose EXACTLY: `PrerequisiteHasCourseUnlocked`
   **50**, `PrerequisiteHasCourseRunning` **13**,
   `PrerequisiteHasCourseAtLevel` **3**, `CharacterModifier_XP` **2**
   (68 total — measured independently from the stub census, agreeing
   row-for-row).
2. The piece-02 walker is NOT blind to typed blocks. Executing
   `relink_util.walk_pptr_refs()` on the real
   `CareerChallenge_Course_Archaeology_V1` stub returns exactly
   `{fieldPath: "references.00000000.data._course", m_FileID: 2,
   m_PathID: -7906850020505022578}` (plus `Objectives[]`). Generic
   descent reaches `fields.references[*].data`.
3. `_unresolved_pptrs.jsonl` (2,391 rows) holds **zero**
   career-challenge / prerequisite / `_course` rows — because those PPtrs
   RESOLVED upstream, not because they were never attempted.
4. Why everyone missed it: pair files never name typed classes, so the
   F6 probe's grep for `PrerequisiteHasCourseUnlocked` in `relinks/**`
   could only ever return zero. verifyB 5.1's "no pathId-level resolver
   exists in relinks" is likewise stale against the current corpus.

**Ruled:** ownership stays with the LOGIC stage — but on the correct
grounds, and with teeth added:

- **Correct grounds:** relinks' 68 rows are anonymous PPtr relations.
  They carry no `prerequisiteClass`, no verb, no payload, no taxonomy
  membership, no non-member separation, no unlock-edge semantics. That
  enrichment (plus the census/sidecar artifacts only a typed-block view
  can produce) is logic-layer work. Sole-writer law stands: stage 8
  never writes `relinks/**`, no piece-02 revision is owed, and §6's
  non-goal text survives unchanged.
- **The typed-block walker stays justified — with honest wording.** Its
  true raison d'être is that plain PPtr walking yields `(fieldPath,
  fileId, pathId)` leaves WITHOUT type attribution; the census,
  non-member routing, and semantic verb require the
  `data`+`type` view. It is not needed to "find" the PPtrs.
- **Mandatory reconciliation leg (new, binding — see RF-2):** because
  two layers of the corpus will now describe the same facts, silent
  divergence must be impossible. Every resolved unlock edge MUST be
  matched against relinks' `config_config` rows on
  `(srcBundle, srcPathId, dstPathId)`; the run section reports
  `relinksCoursePPTRRows` (seed 68), `unlockEdgeOverlapWithRelinks`
  (seed 50), `declaredScopeDifference` (seed 18 = 13 HasCourseRunning +
  3 HasCourseAtLevel + 2 CharacterModifier_XP, which logic deliberately
  does NOT emit as unlock edges); any overlap ≠ resolved-count mismatch
  or unexplained relinks-side counterpart is a named gap row / DRIFT —
  never silence. This mirrors the spec's own existing
  "cross-check only, never mutated" stance toward `matrix.json`.
