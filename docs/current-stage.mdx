# Current-stage reconciliation

## Executive verdict

The implementation is a mature extraction pipeline, not an early bootstrap and
not a site-ready product. Plans and code align only when the project is labeled
**Phase C: data hardening and proof closure**.

The repository had drifted into three mutually incompatible stories:

1. root documents said nothing had been extracted;
2. generated evidence showed thirteen implemented stages and substantial real
   data;
3. an earlier branch state added a generic public site and analytics as though
   the frontend gate had opened.

This review resolves the conflict in favor of measured code/evidence and the
data-before-frontend rule:

- canonical docs now describe the real pipeline;
- the premature site tree is removed;
- unresolved implementation findings are promoted into current blockers;
- dated scouts/specs/rulings are retained as evidence, not status;
- transcript-style reviews/verifications are consolidated and removed.

## Removed implementation

The former site contained:

- one English-only centered hero;
- a system-font dark palette;
- metadata claiming database, maps, tools, guides, news, calculators, and full
  locale coverage;
- PostHog initialization.

From code alone, it had none of the required entity object hierarchy,
game-derived visual tokens, locale routing, search, map, tools, relation
modules, public data API, structured data, UGC, or game assets. It was a
generic marketing shell and its claims exceeded the implementation. Removing
it aligns visuals, architecture, and sequencing simultaneously.

Analytics can return only when a real public candidate exists, a production
origin is assigned, and measurement is part of that candidate rather than the
reason a shell exists.

## Plan alignment

### Extraction plan

The old piece-1 language is superseded by the thirteen-stage registry. Piece
specs remain contracts. Current work is fix/review/proof, not adding another
parallel plan.

### Map plan

The product still owes an owned, bidirectionally linked campus map and the
flagship campus planner. The map is desktop/TV only; mobile database pages link
to it instead of embedding an interactive canvas. No frontend work starts
until map identities are sound.

### Localization plan

All 13 client locales remain mandatory. Pivot English uses bare paths. Every
other locale uses a localized prefix, localized section segment, and
localized entity slug generated by one route service.

### Site/content plan

Database, map, news, guides, tools, glossary/FAQ, changelog, search, comments,
corrections, accounts, feeds, roadmap, and feedback remain in scope. They are
not represented by empty routes or promise copy while data is incomplete.
[`docs/site-plan.mdx`](site-plan.mdx) is the product contract.
[`docs/design-direction.mdx`](design-direction.mdx) is the visual bar. Phase D
starts with extracted visual tokens, one entity object, then map and planner —
not a marketing homepage.

### Distribution plan

Skill and MCP repositories are release-parallel work only after extracted
texts, translations, images, and relinks are verified exhausted and the public
site exists. No empty registry artifact is created now.

## Review status

Pull-request review verdicts live in the GitHub conversation, not in this
reconciliation. Remaining “review” blockers here are stage-specific implementation reviews
that can close only after the corresponding code and corpus changes. They do
not commission new tests in this pack.

## Exit criteria for Phase C

The phase closes only when:

- map identities and joins pass real-corpus assertions;
- media and model output reconciles to the source universe;
- three competitor models are applied;
- all corpus artifacts are committed or explicitly staged under size policy;
- current reviewed source hashes reproduce the data;
- PROOF and validation are generated from that run;
- stage-specific implementation reviews leave no unresolved finding.
